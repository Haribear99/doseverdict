# 원샷 + 같은 인용 판정기, 결함 없는 판 비교 — 사전 등록 (2026-09-30, 실행 전 커밋)

## 질문
독립 심사의 치명 지적은 "에이전트 구조가 결함 탐지를 낫게 한다는 사전 등록 증거가 없다"였다. 원 20에서는 이미 답이 나와 있다(원샷 대비 grounded 차이 확인 안 됨, `docs/oneshot_prereg.md`). 그리고 같은 인용 판정기를 원샷에 씌운 사후 비교도 이미 봤다(`app/eval/oneshot.py::post_hoc`, 기술서 6.10).

**아직 보지 않은 것은 결함 없는 판에서의 비교다.** 에이전트는 결함 없는 기준 시놉시스에서 실행당 기준 문장 8.0개를 지적했다(defect finding 6.42, 특이도 0.64, `docs/specificity_prereg.md` 평가 B). 이 질문은 다음과 같다. 같은 모델을 도구 없이 한 번 부르고 그 인용을 같은 판정기로 거르면, 결함 없는 판에서 더 조용한가, 더 시끄러운가.

## 이미 본 것(블라인드 아님)
- 원 20에서 원샷·원샷+판정기의 grounded 결과(사후 표)는 이미 봤다. 그래서 원 20 수치는 이 문서의 1차 판정에 쓰지 않는다.
- 에이전트의 결함 없는 판 결과(평가 B)도 이미 봤다. 코드 점검 중 에이전트 쪽 값을 다시 계산했다(지적 기준 문장 8.0/실행, verified만 7.5/실행). 새로 실행하는 쪽은 원샷뿐이다.

## 표본
- 결함 없는 기준 시놉시스 4종(`app/demo/{sotorasib,adagrasib,lorlatinib,dv505}_synopsis_fixed.md`) × 3회 = 원샷 12회.
- 호출은 기존 `app/eval/run_eval.py::run_oneshot`을 그대로 쓴다(gpt-6-sol, reasoning medium, 도구·검색 없음, 문서 목록만).
- 에이전트 쪽은 기존 `results/states/clean_base/`(현재 기본 설정 12회)를 그대로 쓴다. 다시 돌리지 않는다.

## 팔
| 팔 | 정의 |
|---|---|
| 에이전트 | clean_base 12회. 판정이 defect인 finding 전부(F00 제외). 평가 B와 같은 정의다 |
| 원샷(원) | 원샷 finding 전부 |
| **원샷 + 판정기(1차)** | 원샷 finding 중 `guidance_quote`가 인용 문서 조항과 원문 일치하거나 NLI 의역(entailment ≥ 0.7, 가까운 조항 3개)으로 인정된 것만. 구현은 `oneshot._support(mode="nli")`이고 원 20 사후 분석과 같은 판정기다 |
| 원샷 + 판정기(원문 일치만) | `mode="exact"` |

## 지표와 판정(사전 고정)
- **1차 지표**: 실행당 지적된 기준 문장 수. 기준 문장 분할은 `specificity.sentences`, 겹침 판정은 `specificity.flagged`(`run_eval.matches`)로 평가 B와 같다.
- **1차 비교**: (원샷+판정기) − 에이전트의 실행당 평균 차이. 두 팔에서 실행을 각각 복원 추출하는 부트스트랩(5,000회, seed 0)으로 95% CI를 구한다.
  - CI 상한 < 0 → **"원샷+판정기가 결함 없는 판에서 더 조용하다"**
  - CI 하한 > 0 → **"에이전트가 결함 없는 판에서 더 조용하다"**
  - 그 외 → **"차이 확인 안 됨"**
- **2차(기술용)**: 특이도, 실행당 finding 수, 원샷(원)·원문 일치만 팔의 같은 지표, 토큰/실행. 에이전트 verified 상태 finding만 센 값도 병기한다.

## 결과별 보고 방침(사전 고정)
- **어느 결과든 덱의 한계·부정 결과 장과 기술서 6.10에 그대로 싣는다.** 판정 문구는 위 세 가지 중 하나를 그대로 쓴다.
- "원샷+판정기가 더 조용하다"가 나오면, "에이전트는 토큰 약 8배를 쓰고 결함 없는 판에서 더 많이 지적한다"를 한계로 명시한다.
- "에이전트가 더 조용하다"가 나와도 "에이전트 구조가 탐지를 낫게 한다"로 쓰지 않는다. 이 실험은 결함 없는 판 4종 × 3회의 소음만 본다. 판정기는 인용 판정기이며, 에이전트 검증기 전체(프로토콜 쪽 검사·보류·재작성)가 아니다.

## 한계(사전 인정)
- 기준 시놉시스는 팀이 "정상판"으로 쓴 것이다. 실제 결함이 남아 있을 수 있다.
- 기준 시놉시스는 4종뿐이고, 실행은 서로 독립이 아니다(같은 문서 3회). CI는 과소 추정일 수 있다.
- 원샷에는 기권 선택지가 없다.
- 에이전트 clean_base는 09-30에, 원샷은 이번에 실행한다. 게이트웨이 모델 버전이 같은지는 감사로그의 모델명으로만 확인한다.
