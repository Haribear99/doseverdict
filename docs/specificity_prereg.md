# 특이도 평가 — 사전 등록 (2026-09-30, 계산·실행 전 커밋)

## 질문
DoseVerdict는 "무엇이든 지적"하는가, 결함이 있는 문장을 골라 짚는가. 또 에이전트가 낸 수정안을 적용하면 같은 문장을 다시 지적하지 않는가.

독립 심사에서 받은 비판("43/43 지적은 특이도 0과 구별되지 않는다", "고치면 조용해지는가")에 답하려는 평가다.

## 문장 단위 정답
평가 케이스는 결함 없는 기준 시놉시스(`app/demo/*_fixed.md`)의 각 섹션 끝에 규범 위반 문장을 덧붙여 만들었다(`app/eval/inject.py::build_cases`). 그래서 문장마다 정답이 정해진다.
- **주입 문장** = 결함(양성). `defects[].protocol_sentence`.
- **기준 문장** = 결함 없음으로 **가정**(음성). 기준 시놉시스를 문장으로 나눈 것이다. 제목(#)·20자 미만·메타데이터 줄(Title·Sponsor 줄, `>` 고지문)은 뺀다(지적될 일이 없어 특이도를 부풀린다).
  - 한계: 기준 시놉시스는 팀이 "정상판"으로 쓴 것이다. 실제 결함이 남아 있을 수 있으므로 특이도는 **하한**이다.

## 평가 A — 기존 저장 상태 분석(토큰 0)
- **대상**: 최종 코드 실행 70케이스 — 원 20 × 2회(`lean_v3`, `lean_v3b`)와 다약물 30(`lean_mdrug3`). 저장 상태는 이미 있지만, 이 분석 규칙은 계산 전에 커밋한다.
- **지적된 문장**: 판정이 `defect`인 finding의 `protocol_span`이 그 문장과 겹치는 경우다(`run_eval.matches`, 채점과 같은 규칙). F00 같은 결정론 기권 finding은 뺀다.
- **지표**
  - 민감도 = 지적된 주입 문장 / 주입 문장
  - 특이도 = 1 − 지적된 기준 문장 / 기준 문장
  - Youden J = 민감도 + 특이도 − 1
  - 케이스 단위 부트스트랩 95% CI(5,000회, seed 0)
- **판정**: J의 CI 하한이 0보다 크면 "주입 문장을 기준 문장보다 골라 짚는다", 아니면 "구별 확인 안 됨"이라고 쓴다.
- **추가 보고**: 여러 케이스에서 반복해서 지적된 기준 문장 상위 목록. 기준 시놉시스의 실제 결함 후보인지 체계적 오경보인지 사람이 볼 수 있게 공개한다.

## 평가 B — 결함 없는 기준 시놉시스 실행(음성 대조)
- 기준 시놉시스 4종(소토라십·아다그라십·로를라티닙·DV-505 `_fixed.md`)을 현재 기본 설정으로 3회씩, 총 12회 실행한다.
- 지표: 실행당 지적된 기준 문장 수, 특이도, defect finding 수. 평가 A의 기준 문장 특이도와 비교한다. 주입 문장이 있을 때 기준 문장을 더 지적하는지를 보는 문맥 효과다.

## 평가 C — 수정안 적용 후 재검토
- 원 20케이스의 `lean_v3` 상태에서 수정안(`suggested_patch`)이 있는 defect finding의 `protocol_span`을 수정안으로 치환해 "수정판"을 만든다. 결정론 변환이다. 수정안이 있는 케이스만 대상으로 한다.
- 현재 기본 설정으로 1회 재검토한다.
- 지표
  - 수정된 문장이 재검토에서 다시 지적된 비율(1차): 수정안 텍스트와 겹치는 defect finding이 있으면 재지적이다.
  - 수정 전후 defect finding 수
  - 수정되지 않은 주입 문장의 지적 유지율: 다른 지적이 흔들리지 않는지 본다.
- 한계: 결함 지적 167건 중 수정안이 붙은 것은 30건(18%)뿐이다. 수정안의 질은 평가하지 않는다(재지적 여부만 본다).
