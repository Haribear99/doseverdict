# 토큰 예산 계획 (팀 누적 3,000만 토큰)

> 09-22 공지로 총 한도가 6,000만 토큰으로 늘었다. 아래 표는 증액 전(3,000만 기준)에 세운 최초 계획이며, 실제 사용량은 `docs/numbers.md` §4와 `docs/token_ledger.md`를 따른다.

본선 배점 "리소스 활용 효율성 15점"의 근거 문서. 모든 호출은 `app/llm/client.py`가 `logs/*.jsonl`에
모델·프롬프트 해시·usage·`x-team-*` 헤더를 기록하며, 최종 보고서에 집계표를 싣는다.

| 용도 | 배정 | 토큰 | 통제 수단 |
|---|---:|---:|---|
| 개발·디버깅 | 20% | 6,000,000 | 개발 중 `DV_RUN_TOKEN_BUDGET=60000`, Luna 우선 |
| 평가셋 생성(결함 주입, 라벨 60건 정리) | 10% | 3,000,000 | Luna, 배치 캐시 |
| 베이스라인·ablation·본평가 | 40% | 12,000,000 | 케이스당 예산 상한, 사전 파일럿 3건으로 외삽 후 실행 |
| 시연·영상·리허설 | 15% | 4,500,000 | 시연 케이스 3건 고정, 재현 실행 캐시 |
| 예비(재실행·Astra 개방 시 재측정) | 15% | 4,500,000 | 승인 없이 사용 금지 |

## 역할별 모델 (`.env`의 `DV_MODEL_*`)

| 역할 | 기본 | 이유 |
|---|---|---|
| planner / reviewer | gpt-5.6-sol | 계획·재계획·상충 의견은 추론 품질이 결과를 좌우 |
| extract | gpt-5.6-terra | 구조화 추출은 Structured Outputs 준수율이 중요, 비용 중간 |
| bulk | gpt-5.6-luna | 결함 주입 생성·요약·대량 평가 |

토큰 과금이 모델별로 동일한지(헤더 `x-team-tokens-consumed` 실측)는 `app/llm/smoke_test.py` 결과(`docs/gateway_probe.md`)로 확정한다.
동일하면 Sol 비중을 높이고, 가중 과금이면 위 표를 유지한다.

## run당 상한 (제안서 종료 조건)

- `Budget.max_tokens` 기본 150,000 / `max_tool_calls` 60 / Gap당 재계획 3회
- 상한 초과 시 결론을 만들지 않고 `terminal_status="no_conclusion"`으로 사람에게 넘긴다.
