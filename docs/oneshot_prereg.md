# 강한 LLM 원샷 베이스라인 — 사전 등록 (2026-09-29, 실행 전 커밋)

## 질문
같은 모델(gpt-6-sol)을 도구·검색·검증 없이 한 번 부르면, 에이전트(DoseVerdict 현재 기본)만큼 결함을 찾고 올바른 규범으로 근거를 대는가. 즉 에이전트 구조가 모델 단독보다 나은가.

## 표본
축① 원 세트 20케이스(`app/eval/data/gold_axis1.jsonl`, AX1-001~020). 에이전트는 이미 있는 최종 코드 2회 실행(`lean_v3`, `lean_v3b`)을 쓴다. 새로 돌리지 않는다.

## 베이스라인 팔
| 팔 | 설정 | 실행 |
|---|---|---|
| `oneshot` | gpt-6-sol 단일 호출, reasoning effort **medium**, 도구·검색·검증 없음. 인용용으로 코퍼스 문서 목록(doc_id·제목·기관·시행일, **본문 없음**)만 준다. 출력: 결함마다 원문 span, 범주, 중증도, 주장, cited_doc_id, 가이던스 문장(기억으로 적음) | 2회(`oneshot`, `oneshot_r2`) |
| `single_rag6` | 09-11 `single_rag`와 같은 절차(코퍼스 검색 1회 8조항 + 단일 호출)를 현재 모델(gpt-6-sol)로 | 1회 |

## 지표와 판정(사전 고정)
- **1차: grounded recall**(정답 규범 문서 인용 또는 원 규범 문장과 겹침 — `run_eval._grounded`, 기존 정의 그대로). 케이스별로 에이전트 2회 평균과 원샷 2회 평균의 차이를 쌍대 부트스트랩(5,000회, seed 0)한다.
  - CI 하한 > 0 → "에이전트 우위", CI 상한 < 0 → "원샷 우위", 그 외 → "차이 확인 안 됨".
- 2차(기술용): span recall, precision proxy, 토큰/케이스(같은 쌍대 방식).
- 2차: **인용 충실도** — 베이스라인 finding 중 가이던스 문장이 코퍼스의 실제 조항과 일치하는 비율(같은 doc_id의 조항 중 하나와: 정규화 문자열이 통째로 포함되거나, 인용문 6-gram의 50% 이상이 그 조항에 있거나(인용문 gram 10개 이상일 때), 6-gram Jaccard ≥ 0.5. 구현 `app/eval/oneshot.py::quote_fidelity`). 에이전트의 인용문은 검색된 조항 원문에서만 오므로 구조적으로 1이다. 따라서 이 값은 비교가 아니라 베이스라인의 인용 환각 정도로 보고한다.
- 검증 통과율은 베이스라인에 검증기가 없어 비교하지 않는다.
- `single_rag6`는 1회 실행이라 에이전트 2회 평균과 비교한 결과를 기술용으로만 보고한다.
