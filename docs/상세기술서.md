# DoseVerdict 상세기술서

제4회 JUMP AI Agentic Drug Challenge 본선 · 분야 3 규제 대응 및 지능형 임상 설계 · 2026-10-02(KST) 기준

**MTD는 RP2D가 아니다: 항암 1/2상 프로토콜의 용량 근거를 계산으로 검증하는 의사결정지원 에이전트**

소토라십의 승인 용량은 960 mg이고, 라벨 12.3은 180\~960 mg에서 정상상태 노출이 비슷하다고 적는다. FDA는 2021년 5월 가속승인과 함께 960 대 240 mg 무작위 비교를 시판 후 요구사항으로 부과했고, 209명이 배정됐다. 2023년 12월 이행이 확인됐고 960 mg은 라벨 용량으로 유지됐다. 1상 초록은 용량제한독성이 관찰되지 않았다고 보고한다. 묻는 것은 그 용량을 비교 없이 RP2D로 넘긴 근거다. DoseVerdict는 RP2D를 정하는 프로토콜 개정 단계에서 이 근거를 계산한다. 증량 코호트 규모로는 노출 포화를 확정할 수 없으므로 판정 대신 용량군별 반복투여 PK를 요청하고, 판정이 지표나 PK 가정에 따라 갈리면 결론을 내리지 않는다(6.5절).

| 하는 것 | 하지 않는 것 |
|---|---|
| 프로토콜을 구조화하고 용량 근거의 결측·상충을 찾는다 | 용량의 정오나 효능·안전성의 정답을 판정하지 않는다 |
| TCR과 설계 운영특성을 도구로 계산한다. TCR은 C_max·C_avg·C_trough로 함께 낸다 | 수치 판정을 LLM에 맡기지 않는다 |
| 판정이 지표나 PK 가정에 따라 갈리면 기권하고 추가 PK를 요청한다 | 비어 있는 PK를 전형값으로 채우지 않는다 |
| 지적마다 규제 원문 조항, 계산값, 기권 사유를 붙인다 | 구조 알림에서 독성 장기를 추론하지 않는다 |
| 검토 메모를 내고, 승인 여부는 사람이 정한다 | 비항암 적응증, 제출 문서 자동 작성, 자동 승인은 지원하지 않는다 |

실제 승인 전 1상 초록 43건으로 한 후향 검증은 null이었다(6.8절).

실행: https://huggingface.co/spaces/Haribear99/doseverdict?demo=1&cached=1 에서 저장된 결과를 바로 볼 수 있다. 라이브 검토와 그 밖의 실행 방법은 8.1절에 있다.

## 초록

DoseVerdict는 프로토콜을 Trial Schema로 구조화하고, 결측·상충 규칙으로 검토 과제를 정한다. LLM은 과제별 가설과 검색 질의를 만든다. 근거는 RDKit·ChEMBL·openFDA·Open Targets·설계 몬테카를로·규제 코퍼스 검색·ClinicalTrials.gov 호출로 모은다(ClinicalTrials.gov는 설계 구조 비교에만 호출한다). 인용 검증기는 NLI와 규범 강도 규칙으로 근거가 받치지 못하는 문장을 보류하거나 기각한다. 수치 판정은 도구가 내리고, 판정이 갈리면 기권한다. 소토라십 240 mg이 그 사례다(6.5절). 최종 승인은 사람이 한다.

평가는 전문가 라벨이 없는 합성 Silver Set 위에서 했다. 원 20, 확장 40, 다약물 30케이스다. 유의하다고 적은 차이는 케이스 단위 쌍대 부트스트랩 95% CI가 0을 포함하지 않는 경우다. 현재 기본 설정은 전 노드 gpt-6-sol, strict, 근거 인용문 250자이고, 이를 09-11 배포 기본값(lean)과 비교했다.

|---|---|---|---|
| 원 20케이스 | 같은 설정 2회 평균 대 lean 1회 | 토큰 −10.4%, 검증 통과율 +0.044 [+0.012, +0.071], grounded +0.075 [+0.012, +0.138] | 6.3 |
| 확장 40케이스 | 09-23 경화 기준선 대비 | 토큰 −17.8%, grounded +0.046 [−0.017, +0.104]로 유의하지 않음 | 6.3 |
| 다약물 30케이스 | 최종 코드 | span 0.933, grounded 0.450 [0.378, 0.522], 검증 통과율 0.961 | 6.4 |

같은 설정을 두 번 돌리자 grounded가 0.067 흔들렸다. 그래서 grounded 차이는 방향만 확인했고 크기는 확정하지 않는다. 1회 실행 회귀 판정 하나는 같은 코드 재실행에서 기각이 보류로 바뀌었다(6.3절). 케이스당 토큰은 3.9만\~4.0만, 검증 통과율은 0.961\~0.975이고, 7개 실행 180케이스에서 LLM 출력 실패는 0이다. strict와 250자는 사후 기준으로 채택했다(6.2절). 다약물 세트의 결함 문장 84개는 원 세트와 같은 풀에서 왔다. 새 결함 유형으로의 일반화는 보여 주지 않는다(6.4절).

사후 분석에서 차이가 보인 곳은 인용이다. 같은 판정기로 근거 문장을 인용 문서의 조항과 대조하면 에이전트는 94\~98%, 원샷은 55\~77%가 확인됐다. 이 판정기는 에이전트에 유리한 한계가 있다(6.9절). 원 20 문장 단위 판별력은 사후 점추정에서 비교 조건에 따라 순서가 갈렸다(6.13절). 도구 없는 같은 모델은 자료가 없으면 판정을 멈췄고, 판정한 약은 프로토콜에 PK가 적힌 1종뿐이었다(판정 범위 0.25). 사후 조건(A′)에서 추정해서 판정하라고 하면, PK가 라벨에만 있는 약에서 3회 판정이 일치한 비율은 26.7%였다. 이 값은 정답을 쓰지 않는 모델 내부 재현성 지표다. 같은 지시문으로 사전 등록 실행에서 다시 재면 같은 3종에서 0.533(4약 전체 0.650)이라 26.7%는 재현되지 않았고, 원샷이 고른 입력에 결정론 계산기를 붙여도 4약 0.700이었다(판정 문구 없는 기술 통계, 판정값 분포는 6.15절). 에이전트는 1.000이었다. 에이전트 1.000은 이미 관측된 값이고 도구 정답과 같은 계산 경로라 순환적이며, 결정론 조회 규약의 성질일 뿐 LLM 에이전트가 필요하다는 근거가 아니다(규칙 조회 팔 미실행, 6.15절). 사전 등록 1차 지표인 지적 문장 집합의 3회 일관성은 판정이 '이 시놉시스 4종에서 차이 확인 안 됨'이었고, 방향은 에이전트가 덜 일관된 쪽이었다(에이전트 − 원샷 −0.059, 약 4종 중 3종에서 에이전트가 낮음, 6.15절). 이 결과들이 받치는 범위는 입력을 도구로 확보해 고정하고, 원문에 묶인 인용과 기권 사유를 남기는 데까지다.

배포본(HF Spaces CPU)의 라이브 검토는 웜 상태에서 83초가 걸렸다. 1회 측정이다. 배포 검증 중 규제 조항 검색이 첫 배포부터 동작하지 않던 결함을 발견해 고쳤다(8.3절).

## 1. 문제 정의

- 사용자: 한·미 1/2상 신청을 준비하는 임상개발 책임자. 규제담당자와 시험책임자가 검토에 함께 참여한다.
- 실패 모드: 노출이 포화됐거나 독성 부담이 기록돼 있는데도, 용량 비교 계획 없이 MTD 인접 용량으로 확장 코호트에 들어가는 경우다. 소토라십 라벨 12.3에는 180\~960 mg 노출 유사로 적혀 있다. FDA는 2024-08 최종 가이던스에서 다용량 비교를 권고한다. 식약처는 민원인 안내서(안내서-1443-01, 본문 기준 2025-08-29 제정, 웹 등록 2025-11-17)로 안내한다. 두 문서의 규범 강도는 다르다.
- 연구 질문: 프로토콜 문장 하나를 두고 "이 결론을 지탱할 자료가 프로토콜 안에 있는가"를 계산과 문서로 판정할 수 있는가. 그리고 판정이 갈릴 때 멈출 수 있는가.
- 적용 범위: 항암제 1/2상의 용량·CTQ·실행 가능성까지다. 효능·안전성의 정답 판정, 비항암 적응증, 제출 문서 자동 작성은 **지원하지 않는다**.
- 약물 범위(09-26 약물 무관화): 약리 입력은 다음 경로로 얻는다.
  - ChEMBL ID: 프로토콜 기재 → 캐시 표 → 성분명 검색(정확한 이름 일치만)
  - 라벨: 브랜드 → 성분명 → 전문 검색(제품명 일치 확인)
  - TCR용 PK: ① 승인 라벨 ② 프로토콜 보고값 ③ 없으면 기권. 소토라십 기본값(MW·IC50·CV)은 제거했다.
  - 투여 간격: 프로토콜 → "1일 2회" 표기 → 1일 1회 가정(표기)
  - f_u: 라벨·프로토콜에 단백결합 값이 없으면 cLogP 추정치를 쓰고 "추정"으로 표기한다.
  - 한계: 라벨 PK 파서는 실제 라벨 6종의 표현으로만 검증했다. 코드명도 ChEMBL 이름 검색을 시도하며, 등록되지 않은 코드명(DV-505)은 미발견으로 기록된다.
- MTD/MAD가 유일한 활성 용량이면 "MTD≠RP2D" 판정 대상이 아니다. 이를 자동으로 판별하는 기능은 구현하지 않았고, 사용자가 판단한다.

## 2. 관련 기준과 기존 도구

- 기준 문서: FDA *Optimizing the Dosage of Human Prescription Drugs and Biological Products for the Treatment of Oncologic Diseases*(Final 2024-08), FDA Expansion Cohorts(2022-03), FDA AI 신뢰성 초안(2025-01), FDA 방사성의약품 용량최적화 초안(2025), ICH E6(R3)(2025-01-06 Step 4), ICH E4, 식약처 안내서-1443-01(2025-08-29).
- 공백: 기존 도구(BOIN Suite, PBPK/QSP, 임상운영 플랫폼)는 무엇을 계산할지 이미 아는 사용자를 위한 것이다. DoseVerdict는 그 사이의 **연결 계층**을 채운다. 프로토콜 문장에서 계산으로, 계산에서 조항 대조로 넘어간 뒤, 대조 결과를 문장 단위 수정안으로 되돌리는 흐름이다.

## 3. 시스템 설계

### 3.1 상태 객체와 판정 권한

상태 객체는 `ReviewState = {TrialSchema, tasks(DAG), evidence, findings, tool_log, replan_events, budget, audit}`(Pydantic)이다. 판정 권한은 아래와 같이 나눈다.

| 판정 | 담당 | LLM의 역할 |
|---|---|---|
| 구조화·가설·문장 초안 | LLM(gpt-6-sol) | 수행 |
| 수치 판정(TCR·설계 운영특성·표본수) | 도구(결정론 계산) | 없음. LLM finding이 TCR 판정을 담으면 보류(held)한다. 설계·표본수 수치 주장의 자동 차단은 구현하지 않았다 |
| 규범 판정(인용 적합성) | 검색 + NLI 검증기 + 규범 강도 규칙 | 없음 |
| 최종 승인 | 사람(Human Gate) | 없음 |

### 3.2 노드(LangGraph 1.2)

compile → plan → tools → arena → findings → verify ⇄ rewrite → gate(interrupt) → finalize

- Orchestrator(plan)의 도구 선택 규칙:
  - SMILES가 있으면 RDKit·ChEMBL을 호출한다.
  - 용량군이 3개 이상이면 설계 시뮬레이션을 돌린다.
  - 타겟이 언급되면 Open Targets·openFDA를 호출한다.
  - 대상국이 n개면 규제 검색을 n회 한다.
  - 결측이 있으면 "근거 미확보"로 표기한다.
  - 종료 조건은 토큰·도구 예산과 재계획 3회이고, 기본값은 "결론 없음"이다.
- 도구 11종: `tool_log`의 도구 이름 기준이며, 같은 도구를 반복 호출해도 1종으로 센다.
  - `rdkit.structure_profile`
  - `chembl.potency`, `chembl.lookup`(성분명 → ID, 09-26)
  - `opentargets.target_evidence`
  - `openfda.label`
  - `pharm.tcr_three_metrics`
  - `pharm.exposure_power`
  - `design.compare_sample_matched`
  - `design.required_sample_for_pcs`
  - `corpus.search`
  - `ctgov.search_analog_trials`
- 규제 코퍼스: 7종 PDF를 절 단위로 청킹한 396절이다. bge-m3 dense와 BM25를 RRF로 결합하고, 국가별(KR/US/common)로 나눠 검색한다. 각 절에는 규범 강도·발효일·버전 메타를 붙였다.
  - 문서별 절 수: ICH E6(R3) 232, FDA AI 신뢰성 초안 46, FDA 확장 코호트 41, ICH E4 27, FDA 방사성의약품 초안 20, FDA 용량최적화 최종 19, 식약처 1443-01 11(합계 396, `app/corpus/index/clauses.jsonl`).
  - 한계: 절의 59%가 GCP 일반 원칙(ICH E6)이어서 용량 관련 조항의 비중이 작다. 목록에는 있지만 본문을 색인하지 않은 문서가 3종 있다(FDA 용량최적화 2023 초안, 식약처 확장 코호트 안내서, CTTI QbD). 식약처 쪽 근거는 1443-01 한 문서의 11절뿐이다.
- Reviewer: 기본 구성은 규제 Reviewer 1인이다. 시험기관·환자 Reviewer를 더한 3인 구성은 UI 옵션으로 두었다(6.1 ablation에 따른 결정). Reviewer 간 합의는 금지하고 상충을 그대로 표시한다.
- Verifier: claim을 두 부분으로 나눠 검증한다.
  - protocol_fact: 원문 span 실재 검사와 결측 술어 검사
  - evidence_fact: DeBERTa-v3 NLI, entail ≥ 0.7
  - 규범 강도 규칙: 민원인 안내서나 초안을 근거로 '의무화/must'라고 쓰면 기각한다. 폐기 문서를 인용해도 기각한다.
  - 주장과 근거가 모두 한국어면 문자열 대조로, 한쪽만 한국어면 다국어 NLI로 검증한다. 교차언어 NLI는 함의를 과소평가할 수 있다(7절 예시 ① F02).
  - **'verified'가 뜻하는 것과 뜻하지 않는 것.**
    - 뜻하는 것: 원문 span이 실재한다. 프로토콜 쪽 주장은 문자열 대조·NLI를 통과했거나, 주장에 부재 표현("does not", "no ", "without", "only" 등)이 들어 있다(`findings.py`의 `verify_findings`, 결측 술어 목록). 근거 쪽은 인용 조항 중 하나가 LLM이 쓴 근거 문장(evidence_fact)을 함의한다. 근거 문장이 비어 있으면 근거 쪽은 검사 없이 통과한다(`verify_findings`의 `if not ef` 분기). 반대로 근거 쪽이 규범 강도를 어기거나 폐기 초안을 인용하면 즉시 rejected가 된다.
    - 뜻하지 않는 것: 근거 조항이 그 결함 지적을 실제로 뒷받침한다는 추론은 검사하지 않는다. 예시 ①의 F08(21일 DLT 창)·F10(휴약기)은 일반 조항을 근거로 달고도 verified다. 그러므로 verified율(0.962 등)은 "인용이 원문과 맞는 비율"이지 "지적이 타당한 비율"이 아니다.
- 결정론 finding과 불변식(`enforce_invariants`):
  - TCR 판정이 지표에 따라 갈리면 기권(F00)한다.
  - LLM finding이 TCR 판정을 담으면 보류(held)한다. TCR 판정은 도구 finding(F00)만 낸다.
  - Reviewer 간 상충이 해소되지 않으면 기권한다(Reviewer 3인 옵션에서만 동작).
  - 기권에는 반드시 사유가 있어야 한다(`Finding._abstain_needs_reason`).

### 3.4 구조화 출력 경화(09-23)

모든 LLM 출력은 Responses API의 strict `json_schema`로 받는다. 스키마는 Pydantic에서 생성한다. 이후 처리는 다음과 같다.

- Pydantic으로 다시 검증한다.
- 오류 내용을 되먹여 1회 재시도한다. 출력이 `max_output_tokens`에서 잘리면 상한을 1.5배로 늘려 재시도한다.
- 거부(refusal)는 재시도하지 않고 기록한다.

strict 모드가 `dict[str, X]` 필드를 거부해서 `source_spans`를 리스트형(`SourceSpan`)으로 바꿨다. 필드 순서도 "근거 → 판정"으로 바꿔 모델이 근거를 먼저 쓰게 했다. 이전에는 파싱이 실패하면 빈 리스트로 조용히 넘어갔다. 지금은 실패를 집계하고, 핵심 노드(plan·findings)가 실패하면 결론을 내지 않는다.

경화 이후 평가 420케이스(17개 설정)에서 LLM 출력 실패는 1건이었다. strict가 꺼진 `findings effort medium` 팔에서 범주 enum 밖의 값(`expansion_cohort`)이 나왔고, 재시도 뒤 "결론 없음"으로 처리됐다. 실패가 드러나는 설계(fail-closed)가 의도대로 동작한 사례다. strict를 켠 현재 기본 설정에서는 스키마 단계에서 enum이 강제되며, 7개 실행 180케이스에서 실패는 0이다.

### 3.5 보안·예산·감사

- 문서는 `<protocol_document>` 데이터 블록으로만 전달한다. 도구는 allowlist로 제한한다.
- run당 토큰·도구 호출에 상한을 둔다. LLM 호출 전에 예산 가드가 한도 초과를 막는다. 노드별 예상치는 arena 1만×Reviewer 수, findings 1.6만, rewrite 1.5천이다. 노드별 실측 토큰(`budget.by_node`)은 UI·메모에 표시한다.
- 모든 LLM 호출의 모델·effort·프롬프트 해시·usage·쿼터 헤더를 JSONL 감사로그에 남긴다.
- LLM 호출에는 180초 타임아웃과 지수 백오프 재시도를 적용한다. 외부 API의 5xx·연결 오류는 2회 재시도한다.
- LangGraph 체크포인트 역직렬화는 스키마 타입만 허용한다.

## 5. 실험 방법

### 5.1 설정과 지표

지표 정의는 다음과 같다.

- span recall: 주입한 결함 문장을 finding이 가리킨 비율
- grounded recall: 그 finding이 정답 규범 문서를 인용했거나, finding 텍스트가 결함 출처 규범 문장과 6-gram Jaccard ≥ 0.15인 비율. 검증 상태와는 무관하다. 사전에 정의했고 이후 완화하지 않았다.
- precision proxy: 결함에 적중한 finding / 전체 finding. 정상판에 대한 지적은 모두 오경보로 세므로 하한값이다.
- 검증 통과율: verified finding / 전체 finding
- 토큰/케이스: 감사로그 usage 합. reasoning을 포함하며 게이트웨이 차감과 1:1이다.

### 5.2 A/B 사전 판정 규칙(09-23 등록, `app/eval/compare.py`)

같은 케이스끼리 짝지어 쌍대 부트스트랩으로 비교한다.

- 기각: 토큰이 2% 넘게 증가하거나, grounded·검증의 점추정이 5pp 넘게 하락한 경우
- 채택: 토큰 −15% 이상 절감이거나 grounded CI 하한이 0보다 큰 경우
- 그 외: 보류. 확장 세트에서 재확인한다.
- 규칙 문구와 구현의 차이: 등록 문서(`docs/리서치_요약_0923.md` §7, `compare.py` 머리말)의 기각 문구는 "토큰 증가"인데, 구현(`compare.py`)은 2% 허용을 두었다. 이 문서의 판정은 모두 구현 기준이다. 문구 기준이라면 최종 코드 회귀 비교 3회(토큰 +1.0\~1.9%)는 모두 기각이다.
- 사전 계획에는 반복 횟수 K를 정하는 <strong>안정성 감사(15케이스 × 2회)</strong>가 있었지만 수행하지 않았다. 모든 A/B는 1회 실행이며, 이 한계는 6.3절에서 드러났다.

원 세트의 A/B 팔은 각각 한 변수만 바꿨다. 결합 설정은 strict와 250자 두 변수를 동시에 바꿨다. 실험은 최대 2개 병렬 슬롯에서 돌렸다. 소요시간은 동시 부하에 교란될 수 있어 설정 비교의 근거로 쓰지 않는다.

- **Ablation은 부정적이다.**

기권은 "240 mg이면 충분하다"는 판정을 피하려는 설계이기도 하다. (나)는 라벨 12.3이 지지하는 가정이고, 이 가정에서는 240 mg도 표적을 덮는다. 그러나 이후 무작위 비교에서 240 mg은 ORR 24.8% 대 32.7%로 수치상 열등했다(`evidence/검증된_근거_모음.md`). TCR 커버는 효능을 예측하는 지표가 아니다. DoseVerdict가 판정하는 것은 용량의 정오가 아니라 근거 사슬의 결측이다.

소토라십은 공유결합 저해제이므로 가역 IC50에 기반한 TCR은 근사값이다. 공유결합 저해제의 표준 모델인 kinact/K_I 모델은 구현 범위 밖이다. TCR 임계값(<1 미커버, >10 포화 의심)은 이 프로젝트의 잠정값이다.

Silver Set의 결함은 합성이다. 그래서 실제 약에서 FDA의 판단과 맞는지를 따로 물었다. 입력은 승인 전에 출판된 1상 초록 43건(양성 14)이다. 판정 규칙·비교 기준·누설 차단은 실행 전에 커밋했다(`docs/retro_prereg.md`, 커밋 ac01f81·f6dede7).

  - 초록은 프로토콜이 아니다(용량군·PK 채혈 계획이 대부분 빠져 있다).
  - 표적은 ChEMBL 작용기전의 첫 항목이라, 다중 표적 약에서는 대표 표적이 아닐 수 있다(quizartinib → CSF1R).

### 6.9 같은 모델을 한 번 부르면 되지 않나: 강한 LLM 원샷 베이스라인(`docs/numbers.md` 1-5절)

에이전트 구조가 모델 단독보다 나은지를 직접 물었다. 같은 모델(gpt-6-sol)에 프로토콜과 규제 문서 목록(본문 없음)만 주고 effort medium으로 한 번 부르는 원샷을, 원 20케이스에 2회 돌렸다. 판정 규칙은 실행 전에 커밋했다(`docs/oneshot_prereg.md`). 감사로그의 원샷 호출은 41건이다. 본 실행 40건 외에, 사전 등록 커밋 45초 전에 보낸 연결 확인 호출 1건(1케이스)이 있다. 그 호출의 결과 파일은 커밋하지 않았다.

사전 등록 문서는 차이를 "에이전트 − 원샷"으로 적었고, 이 표는 부호가 반대다. 판정은 같다.

- **사전 등록 판정: 차이 확인 안 됨.** grounded 점추정은 에이전트가 높지만 CI가 0을 포함한다. **결함 문장을 찾는 능력(span)은 원샷도 같은 수준이고, 토큰은 8분의 1이다.** 에이전트 구조가 탐지율을 올린다는 증거는 없다. 09-11 ablation(6.1절)과 같은 방향의 결과다.
- 조건은 원샷에 유리하다. 에이전트는 결함 출처 조항을 검색에서 뺀 채(hold-out) 평가했고, 원샷은 모델 기억 속 가이던스에 제한이 없다.
- 인용 충실도(사전 등록 2차, 원샷만): 원샷이 기억으로 적은 가이던스 문장은 코퍼스 원문과 51% 일치했다(검사 가능분 53\~56%). 여기서 '일치'는 정규화 문자열 포함, 인용문 6-gram의 50% 이상이 한 조항에 있음, 또는 Jaccard ≥ 0.5다.
- 사후 분석(사전 등록 밖, red-judge 지적 반영): 사전 등록은 인용 충실도를 원샷만 재도록 했고, 에이전트는 "검색 원문을 인용하므로 구조적으로 일치"한다고 가정했다. 이 가정을 실측으로 바꿨다. finding마다 근거 문장을 같은 판정기로 인용 문서의 조항과 대조했다. 근거 문장은 에이전트의 경우 LLM이 쓴 evidence_fact, 원샷의 경우 기억으로 쓴 guidance_quote다.

| 원샷(2회) | 360 | 197 (54.7%) | 276 (76.7%) | 84 (23.3%) |

  - 에이전트가 근거 풀에 붙인 규제 조항 인용문(evidence.quote) 자체는 1,308/1,308건이 코퍼스 원문이다(정규화한 앞 200자 포함 기준). 원문이 아닐 수 있는 것은 그 위에 LLM이 쓴 근거 문장이다.
  - '둘 다 아님'은 <strong>"인용 문서 안에서 가장 가까운 조항 3개로 확인되지 않음"</strong>이다. "어느 원문으로도 뒷받침되지 않음"과 같은 뜻이 아니다. 판정 NLI(임계 0.7, 조항 3개)는 결과를 본 뒤 정한 단일 설정이고, 판정 모델은 에이전트의 인용 검증기와 같다. 에이전트는 이 판정기를 통과하도록 보류·재작성 루프를 거치므로, 이 비교는 **에이전트에 유리한 비대칭**을 안고 있다.
  - 기준(문자열만 / NLI 포함)에 따라 원샷 값이 0.117과 0.250으로 두 배 차이 난다. 한국어 인용은 문자열 판정이 되지 않아 검사 불가로 뺐다. 해당하는 것은 에이전트의 식약처 안내서 인용 14건뿐이고(원샷 0건), 이들은 grounded 필터에서 불인정으로 빠져 **에이전트에 불리하게** 작용했다.
- 해석: 사전 등록 판정은 "차이 없음"이다. 사후 분석에서 드러난 차이는 탐지율이 아니라 인용이 원문으로 확인되는 정도다. 같은 판정기로 대조했을 때 에이전트의 근거 문장은 94\~98%가 원문과 맞았고, 원샷은 55\~77%였다. 에이전트가 기대할 수 있는 몫은 규제 검토에서 사람이 인용을 다시 찾아 확인하는 비용을 줄이는 것이다. 다만 이 결론은 사후 분석에서 나왔고, 판정기가 에이전트 쪽에 유리하게 짜여 있다는 한계가 있다. 그 대가로 토큰을 8배 쓴다.
- single_rag(검색 1회 + 단일 호출)는 현재 모델에서도 span 0.342였다. 원샷과는 추론 강도(low 대 medium), 출력 상한(3,000 대 12,000), 지시문("발췌만 사용")이 모두 달라 원인을 분리할 수 없다. 1회 실행이라 기술용으로만 싣는다.

### 6.10 도구 없이 같은 모델에게 약리 판정을 물으면: 기권 평가와 입력 규약(`docs/numbers.md` 1‑6절)

6.9절 원샷 비교는 결함 탐지를 봤다. 이번에는 핵심 주장("수치는 도구가 내고, 판정이 갈리면 결론을 만들지 않는다")에 해당하는 약리 판정을 도구 없는 같은 모델에게 물었다. 판정 규칙은 실행 전에 커밋했다(`docs/abstain_prereg.md`).

- 항목: 약 4종(소토라십·아다그라십·로를라티닙·DV-505)의 용량군 20개. 정답은 도구의 TCR 판정이다(판정 보류 7, 커버 13).
- 질문: 원샷(gpt-6-sol, 도구 없음)에 용량별 표적 커버리지 판정을 3회씩 물었다. 지시문에는 기권 선택지(`indeterminate` = 지표에 따라 갈림, `cannot_assess` = 자료 없음)와 그 정의를 줬다.
  - 조건 A: 시놉시스만 준다.
  - 조건 B: 도구가 쓴 PK 입력과 판정 규칙까지 준다.
  - 사후 A′(사전 등록 밖, red-judge 제안): 시놉시스만 주되, 기억·추정을 써서 판정하라고 권한다.

| 지표 | A(시놉시스만) | B(도구 입력) | 사후 A′(기억 권장) |
|---|---|---|---|
| 정답이 판정 보류인 용량군에서 확정 판정(1차) | 0.000 | 0.000 | 0.381 |
| 정답이 커버인 용량군에서 판단 보류 | 0.769 | 0.000 | 0.231 |
| 도구 판정 일치율 | 0.250 | 1.000 | 0.717 |
| 반복 3회 판정 일관성(PK가 라벨에만 있는 약 3종, 사후. A·B는 자명한 값) | 1.000 | 1.000 | 0.267(재측정 0.533, 재현 안 됨, 6.15절) |
| TCR_avg / TCR_trough 상대 오차 중앙값 | 0.004 / 0.0 | 0.003 / 0.002 | 0.51 / 0.544 |

- **조건 A: 사전 등록 1차 지표는 0이었다. 다만 기권 선택지와 판정 규칙을 지시문으로 준 조건에서다.** 판정 보류가 정답인 7건을 나누면 다음과 같다.
  - 5건(소토라십 4, 아다그라십 150 mg)은 자료가 없어 `cannot_assess`로 답했다.
  - 지표에 따라 판정이 갈리는 것을 알아보고 멈춘 것은 DV-505 2건이다.
  - 판정을 낸 약은 프로토콜에 PK가 적힌 DV-505 한 종뿐이다(판정 범위 0.25).
- 조건 B: 입력을 주면 도구와 20/20 같은 판정을 냈다. 그러나 B의 입력은 정답을 만든 도구의 입력 그 자체여서, 이 일치는 거의 정의에 가깝다.
- **사후 A′: 추정해서 판정하라고 하면 모두 판정하지만, 회차마다 입력 가정을 다시 골라 판정이 흔들린다.**
  - PK가 라벨에만 있는 약 3종에서 같은 용량을 3회 물었을 때, 판정이 모두 같은 경우는 26.7%였다. 이 일관성은 정답을 쓰지 않는 모델 내부 지표다.
  - 사전 등록 재측정은 6.15절에 있다(다른 실행: 같은 지시문으로 4약 0.650, 같은 3종 0.533. 판정 문구 없는 기술 통계이며 판정값 분포는 6.15절). 같은 지시문·같은 3종에서 0.267은 재현되지 않았다.
  - 주원인은 기억한 라벨 PK가 아니다. 소토라십(Cmax 7.50 µg/mL)·로를라티닙의 기억한 PK는 회차 간 거의 같았고, 아다그라십은 Cmax가 회차마다 약 2배(2.1\~4.3 µg/mL) 달랐다. 흔들린 것은 모델이 가정으로 고른 IC50(소토라십 30 nM / 6 nM / 0.09 µM, 아다그라십 10 / 50 / 25 nM, 로를라티닙 30 / 80 / 10 nM)과 용량 외삽 방식(용량 비례, 제곱근 등)이다.
  - 도구 판정과의 불일치 17/60 중 9건은 모델이 도구보다 조심한 쪽(정답 커버 → 판정 보류)이고, 8건은 확정 판정을 낸 쪽(판정 보류 → 커버 6, 미커버 2)이다. 불일치는 도구 모형 기준의 차이일 뿐 실제 오답이라는 뜻이 아니다. 라벨 12.3의 "180–960 mg 노출 유사"를 생각하면, 모델의 비선형 외삽이 도구의 선형 근사보다 라벨에 가까운 경우도 있다.
- 해석
  - 이 평가는 에이전트와 원샷의 정확도 비교가 아니다. 에이전트는 같은 도구 판정을 내므로 도구 일치율이 정의상 1이다(순환성).
  - 보여 주는 것은 두 가지다. 기권 선택지가 있으면 모델은 자료 없이 멈춘다(A). 추정하라고 하면 IC50·PK 모형 같은 입력 규약을 매번 다시 정해, 판정이 재현되지 않는다(A′).
  - DoseVerdict의 재현성은 입력 규약을 코드로 고정한 데서 온다. IC50은 ChEMBL 세포 기반 중앙값, PK는 라벨 12.3 → 프로토콜 보고값 순, 모형은 선형 1구획이며, 그 출처를 근거 카드에 남긴다. **이 규약이 옳다는 근거는 아니다.** 선형 근사와 IC50 선택은 6.5절의 한계를 그대로 가진다.
- 한계
  - 계산·기권 행동을 볼 수 있었던 약은 1종(DV-505, 합성 입력), 용량군 5개뿐이다.
  - A′는 사후 조건이다. 반복 일관성 지표와 위 해석은 A′ 결과를 본 뒤 정했다(사후).
  - 입력에 없는 수치 비율(조건 A 0.048)은 분자량 계산값처럼 유도된 수치이며 PK 값이 아니다.
  - 벌점 채점(Kalai 등, Nature 2026)은 벌점을 프롬프트에 고지해야 성립하므로 적용하지 않았다.

### 6.11 무엇이든 지적하나: 문장 단위 특이도와 수정안 재검토(`docs/numbers.md` 1-7절)

후향 검증(6.8절)에서 43/43을 지적한 결과는 "무엇이든 지적한다"는 뜻일 수 있다. 이를 확인하려고, 결함 정답이 문장 단위로 있는 합성 세트로 특이도를 쟀다. 판정 규칙은 계산·실행 전에 커밋했다(`docs/specificity_prereg.md`).

- 문장 단위 정답: 평가 케이스는 결함 없는 기준 시놉시스의 각 섹션 끝에 결함 문장을 덧붙여 만들었다. 덧붙인 문장이 양성이다. 기준 문장은 결함이 없다고 **가정**해 음성으로 두었다. 기준 시놉시스에도 실제 결함이 남아 있을 수 있으므로 특이도는 하한이다.

| 평가 | 조건 | 결과 |
|---|---|---|
| A(기존 70케이스, 토큰 0) | 결함 6개를 넣은 판 | 민감도 0.950 / 0.975 / 0.933, 특이도 0.812 / 0.786 / 0.737, Youden J 0.762 / 0.761 / 0.670(CI 하한 0.609 이상) — 원 20 1·2회차 / 다약물 30 |
| B(음성 대조, 12회) | 결함을 넣지 않은 기준 시놉시스 4종 × 3회 | 문장 특이도 0.64, 실행당 defect finding 6.42 |
| C(수정안 재검토, 14케이스) | 에이전트 수정안 30건을 적용한 판 | 수정한 문장의 재지적률 0.20, defect finding 8.36 → 7.14, 수정하지 않은 주입 결함 지적 49 → 53 |

- A: 사전 등록 판정은 "주입 문장을 골라 짚는다"다. 결함 문장은 93\~98%를 짚었고, 기준 문장은 74\~81%를 그대로 뒀다.
- **B: 결함이 없는 판에서도 조용하지 않았다.** 12회라 CI 없이 점추정으로만 비교한다. 결함 6개를 넣은 판은 원 20 기준 실행당 8.35건(167/20), 결함이 없는 판은 6.4건으로 지적 수 차이가 작다. 결함 수와 크게 상관없이 비슷한 수를 지적하는 경향이다. 기준 문장 특이도(0.64)도 결함을 넣었을 때(0.74\~0.81)보다 낮았다. 주입 결함이 없으면 기준 문장에서 지적거리를 찾는다는 뜻이다.
  - 반복 지적된 기준 문장 상위는 증량 코호트 전원 집중 PK 채혈(33케이스), 1:1 무작위 용량 비교 60명(27케이스) 등이다. 앞의 것은 환자 부담 지적으로 타당할 수 있다. 뒤의 것은 이미 개선된 설계를 다시 문제 삼은 것일 수 있다. 사람이 판정하지는 않았다.
  - 원인으로 본 것은 findings 지시문의 커버리지 요구("가설이 확인된 모든 검토 질문을 다루라")다. 이를 고친 보정판을 사전 등록 A/B로 시험했다(6.12절).
- C: 수정한 문장의 80%(30건 중 24건)는 재검토에서 다시 지적되지 않았다. 비교 기준은 사후에 red-judge가 계산·재현했다. 같은 30개 문장을 수정하지 않은 독립 재실행(`lean_v3b`)에서는 30/30이 다시 지적됐다. 30건은 모두 주입 결함 문장에 붙은 수정안이었고, 수정하지 않은 주입 결함은 계속 잡혔다. 다만 결함 지적 167건 중 수정안이 붙은 것은 30건(18%)뿐이다. 수정안의 질 자체는 평가하지 않았으며, 다시 지적되지 않았다고 해서 옳게 고쳐졌다는 뜻은 아니다.
- 같은 절차를 UI의 "수정안 적용 후 재검토" 기능으로 넣었다(Findings 탭). 에이전트가 자기 수정안을 적용한 판을 다시 검토해, 고친 문장이 다시 지적되는지와 남은 문제를 보여 준다.

### 6.12 지적을 줄이면: 특이도 보정 A/B(`docs/numbers.md` 1-8절)

6.11절 B의 원인으로 본 커버리지 지시를 findings 단계에서 빼고, "인용 근거의 구체 요건을 어길 때만 보고, 0건 허용" 규칙을 넣은 보정판을 시험했다. 사전 등록(`docs/calibration_prereg.md`)은 B 결과를 본 뒤 설계했다.

- **사전 규칙 판정: 기각.** 오경보는 크게 줄었지만 주입 결함 탐지도 0.96에서 0.58로 떨어졌다. 운영점만 옮긴 것이 아니다. 원 20의 Youden J가 0.761에서 0.559로 낮아져 **판별력 자체가 떨어졌다.**

- 보정판은 UI의 "보수적 지적 모드" 선택지로만 두었고, 측정 수치(특이도·민감도·Youden J)를 도움말에 함께 적었다.
- 한계: 보정판 양성은 1회 실행이다. 두 조건 사이의 운영점(예: 규칙 일부만 적용)은 시험하지 않았다.

### 6.13 원샷에 같은 인용 판정기를 씌우면: 결함 없는 판 비교(`docs/numbers.md` 1-9절)

독립 심사의 치명 지적은 "에이전트 구조가 결함 탐지를 낫게 한다는 사전 등록 증거가 없다"였다. 원 20에서 원샷에 같은 인용 판정기를 씌운 비교는 이미 사후 분석으로 봤다(6.9절). 그래서 아직 보지 않은 결함 없는 판에서 사전 등록(`docs/hybrid_prereg.md`, 실행 전 커밋)으로 비교했다. 사전 등록 문서에는 보고 위치가 6.10절로 적혀 있으나, 바뀐 것은 절 번호(6.13)뿐이다. 원샷은 기준 시놉시스 4종 × 3회를 새로 실행했고(토큰 60,648), 에이전트는 6.11절 B의 12회를 그대로 썼다.

### 6.14 오지적을 줄이는 두 번째 시도: 반박 가능한 Review Arena(`docs/numbers.md` 1-10절)

6.13절 결과에 대응해, 제안서의 Adversarial Review Arena가 실제로 반박하도록 만들었다. 코드상 원인은 Arena가 모든 검토 질문에 의견을 하나씩 내면서도 "결함 아님"을 표현할 수단이 없었다는 점이다. 여기에 findings 지시문까지 "가설이 확인된 모든 질문을 다루라"고 요구했다. 반박 모드에서는 Reviewer가 질문마다 먼저 가설을 반박해 보고 stance(`defect / no_defect / insufficient`)를 낸다. 모든 Reviewer가 반박한 질문은 finding으로 만들지 않는다. 도구 판정·검증기·기권·Human Gate는 그대로다. 설계를 6.13절 결과를 본 뒤 정했으므로, 설계에 쓰지 않은 다약물 30을 확인용 세트로 두고 사전 등록했다(`docs/refute_prereg.md`, 실행 전 커밋). 채택 규칙 4개를 모두 충족해야 기본값을 바꾸도록 했다.

| 지표 | 현재 기본 | 반박 모드 |
|---|---|---|
| 결함 없는 판 12회: 지적 기준 문장/실행 · 특이도 | 8.0 · 0.64 | 6.42 · 0.712(차이 −1.58 [−3.33, +0.17]) |
| 원 20: 민감도 · 특이도 · Youden J | 0.962 · 0.799 · 0.761 | 0.883 · 0.793 · 0.676 |
| 다약물 30(확인용): 민감도 · 특이도 · Youden J | 0.933 · 0.737 · 0.670 | 0.839 · 0.796 · 0.634 |
| grounded 차이(반박 − 현재) | — | 원 20 −0.008 [−0.075, +0.063] · 다약물 −0.078 [−0.155, 0.000] |

- **사전 규칙 판정: 기각(현재 기본 유지).** 결함 없는 판의 지적은 줄었지만 CI가 0을 걸쳤고(규칙 1), 민감도가 0.08\~0.09 떨어졌으며(규칙 2), Youden J가 두 세트 모두 낮아졌다(규칙 3). grounded 규칙(4)만 충족했다. 규칙 4는 원 20 대상이며, 다약물 30에서는 −0.078 [−0.155, 0.000]으로 같은 문턱에 못 미쳤다(사후).
- 해석: 6.12절 보정판(구체 요건 위반만 보고)과 이번 반박 모드는 서로 다른 경로로 지적을 줄였다. 그러나 둘 다 주입 결함도 함께 놓쳤고, Youden J가 떨어졌다(보정 0.761→0.559, 반박 0.761→0.676·0.670→0.634). 원 20에서 반박 모드는 특이도도 오르지 않았다. **현재 파이프라인에서 오지적 감소는 판별력 손실을 동반했다.** 그래서 기본값은 민감도를 우선하는 현재 설정으로 두고, 오지적은 Human Gate에서 사람이 기각한다.
- 반박 모드 코드는 스위치(`DV_ARENA_REFUTE`, 기본 끔)로 저장소에 남겼다. UI 선택지로는 제공하지 않는다(사후 결정).
- 한계: 반박 모드는 원 20에서 1회 실행이고, 비교 대상인 현재 설정은 2회 평균이다. Reviewer 1인 구성만 시험했다. 토큰은 약 2.5M을 썼다.

### 6.15 같은 입력이면 같은 판정이 나오나: 반복 일관성(사전 등록 10-01, 실행 10-02 KST, `CONSISTENCY_REPORT.md`)

6.10절의 0.267은 사후 조건(A′)에서 나온 값이라 주장 근거로 쓸 수 없다. 그래서 같은 질문을 사전 등록 지표로 작게 다시 쟀다. 판정 규칙은 실행 전에 커밋했다(`docs/consistency_prereg.md`, 커밋 232aae6). 13.2절 중2(3팔 비교)의 축소판이다. 결과 원본은 `app/eval/data/results/` 아래 `CONSISTENCY_REPORT.md`와 `consistency.json`이다.

- 질문: 같은 시놉시스를 3번 넣으면 같은 판정이 나오는가.
- 표본: 6.10절과 같은 약 4종(소토라십·아다그라십·로를라티닙·DV-505)의 결함 시놉시스와 용량군 20개다. 팔마다 약별 3회 실행했다. 48회 실행 모두 인프라 실패 없이 끝났다. 결과 보고서에서 에이전트 12회의 `terminal_status`가 `running`으로 보이는 것은 평가가 Human Gate의 interrupt에서 멈춘 상태를 저장하기 때문이다(사람 승인 전이라 종료 상태가 기록되지 않는다). 기존 평가 상태도 같다.
- 설계: 하나의 시스템을 세 팔로 비교하지 않고, 지표별로 비교했다. "원샷 + 인용 판정기 + 도구 기권"이라는 하나의 구성은 어느 지표에서도 실행되지 않았다.
  - L2(1차): 지적한 시놉시스 문장 집합의 3회 쌍별 Jaccard 평균이다. 팔은 원샷, 원샷 + NLI 필터(민감도), 에이전트(lean 기본 설정)다. 1차 비교는 에이전트 − 원샷 하나다.
  - L1(기술 통계, 판정 문구 없음): 용량군 중 3회 판정이 모두 같은 비율이다. 팔은 원샷(도구 없음), 원샷 입력 + 결정론 계산기, 에이전트다. 둘째 팔에서 모델은 PK 입력 6개(CL/F, t½, τ, f_u, IC50, MW)만 고르고 판정은 도구가 한다. 에이전트 L1은 기존 실행에서 이미 관측됐으므로 1차에서 뺐다.
  - 추론: 약 단위 정확 부호 뒤집기 검정이다. 약 4종에서는 가능한 최소 양측 p가 0.125다. 그래서 1차 판정은 실행 전부터 "차이 확인 안 됨"으로 정해져 있었고, 이 사실을 사전 등록에 적었다. 결과는 방향 일치 수와 효과 크기로 읽는다.

| L2 팔 | L2 | 약별(소토라십 / 아다그라십 / 로를라티닙 / DV-505) | 회차별 집합 크기 |
|---|---|---|---|
| 원샷 | 0.746 | 0.758 / 0.716 / 0.867 / 0.644 | 7\~11 |
| 원샷 + NLI 필터(민감도) | 0.497 | 0.259 / 0.719 / 0.515 / 0.497 | 4\~11 |
| 에이전트 | 0.687 | 0.758 / 0.686 / 0.685 / 0.622 | 8\~14 |

- 빈 집합 쌍은 세 팔 모두 0이고, 빈 집합 쌍을 뺀 2차 L2는 1차와 같다.
- **사전 등록 판정: "이 시놉시스 4종에서 차이 확인 안 됨".** 에이전트 − 원샷은 −0.059다. 약별로 음수 3, 0이 1(소토라십)이고, 정확 부호 뒤집기 p는 0.250이다. 기술용 부트스트랩 CI [−0.142, −0.007]은 약 4종 재표본 256개를 정확 열거한 값이다. 그 끝은 가장 극단적인 약 하나에 좌우되므로 판정에 쓰지 않는다.
- 방향은 에이전트가 덜 일관된 쪽이다. 사전 등록 때 밝힌 기존 관측과 같은 방향이다. 결함을 고친 시놉시스(다른 문서)에서도 네 약 모두 에이전트의 Jaccard가 낮았다(사후). 에이전트는 회차당 지적 문장이 더 많았다(8\~14 대 7\~11). Jaccard는 집합 크기와 span 길이에 기계적으로 좌우되지만, 이 편향의 방향은 계산하지 않았으며 이 단서로 방향을 바꿔 읽지 않는다.
- 민감도: 같은 원샷 출력에 NLI 필터를 걸면 0.497로 낮아져, 에이전트 − 원샷이 +0.190(양수 3·음수 1)이 된다. 같은 출력의 부분집합이라 1차와 독립된 증거가 아니며, 판정 문구를 만들지 않는다.

| L1 팔 | L1 | 약별 일치/용량군(소토라십 · 아다그라십 · 로를라티닙 · DV-505) | 입력 6개가 3회 같은 약 |
|---|---|---|---|
| 원샷(도구 없음) | 0.650 | 2/5 · 2/4 · 4/6 · 5/5 | 해당 없음(입력을 내지 않음) |
| 원샷 입력 + 결정론 계산기 | 0.700 | 0/5 · 3/4 · 6/6 · 5/5 | 0/4 |
| 에이전트 | 1.000 | 5/5 · 4/4 · 6/6 · 5/5 | 4/4(계산 용량 집합도 같음) |

- 기술 통계이며 판정 문구가 없다. 에이전트 − 원샷은 +0.350(양수 3·0 1, p 0.250), 에이전트 − 원샷 입력 + 계산기는 +0.300(p 0.500), 원샷 입력 + 계산기 − 원샷은 +0.050(p 1.000)이다.
- 판정값 분포는 원샷 covered 35·not_covered 4·indeterminate 21, 원샷 입력 + 계산기 covered 48·indeterminate 12, 에이전트 covered 39·indeterminate 21이다. 세 팔 모두 3회 내내 missing·cannot_assess인 용량군은 없었다.
- 원샷 입력 팔은 회차마다 입력을 다시 골랐다. 가장 크게 흔들린 것은 IC50이다(소토라십 90 / 6 / 6 nM, 로를라티닙 10 / 1.3 / 1.3 nM, 아다그라십 10 / 10 / 5 nM). 소토라십은 0/5였다. 로를라티닙은 IC50과 t½이 바뀌었는데도 판정은 6/6 같았다. 에이전트는 네 약 모두 같은 출처(라벨 12.3, ChEMBL 세포 기반 중앙값, 프로토콜 보고값)에서 같은 입력 6개를 가져왔다.
- 계산기가 결정론적이라 원샷 입력 팔과 에이전트의 L1 변동은 입력 선택에서만 나온다. 계산기를 붙인 원샷 입력 팔이 0.700에 그쳤다는 것은, 일관성이 계산기보다 입력 확보 규약에서 온다는 것을 시사한다. 유의성 없는 기술 비교다. 동등성 마진을 정하지 않았으므로 "계산기만 붙여도 같다"는 주장도 하지 않는다.
- 6.10절 사후 A′의 0.267과는 다른 실행이다. 0.267은 PK가 라벨에만 있는 약 3종의 값이다. 같은 지시문(기억·추정 권장)으로 새로 돌린 이번 원샷 L1은 같은 3종으로 좁히면 8/15 = 0.533, 4종 전체는 0.650이다. 0.267만 떼어 인용하지 않고 이번 사전 등록 값을 쓴다.
- 같은 지시문·같은 3종에서 0.267은 재현되지 않았다(0.533). 3회 일치 지표 자체가 실행 간에 크게 흔들린다는 뜻이다. 이번 0.650·0.700·1.000 비교도 각 팔 1회 실행(약별 3회)의 값으로 읽어야 한다.

해석과 한계

- 이 결과로 "에이전트가 더 일관된다"고 일반화하지 않는다. 확인된 것은 두 가지다. 지적 문장 집합에서는 차이가 확인되지 않았고, 방향은 에이전트가 덜 일관된 쪽이었다. 용량군 판정에서는 에이전트가 3회 모두 같은 입력을 확보했다(아래 순환성 단서).
- 일관성은 정확성이 아니다. 매번 같은 틀린 판정도 1.000이다.
- 에이전트 L1은 이미 관측된 값의 재현이다. 도구 정답을 만든 것과 같은 계산 경로라 순환적이다. 시놉시스도 팀이 이미 본 문서다(블라인드 아님).
- 에이전트의 L1 일관성은 결정론 조회 규약(PK는 라벨 → 프로토콜, IC50은 ChEMBL 세포 기반 중앙값 → 프로토콜)의 성질이다. LLM 없이 규칙 조회 스크립트와 계산기로도 같은 규약을 재현할 수 있으며, 그런 팔은 실행하지 않았다. 따라서 이 결과는 LLM 에이전트가 일관성에 필요하다는 근거가 아니다.
- 판정은 입력 선택에 민감하다. 원샷 입력 팔에서 소토라십 IC50만 90에서 6 nM으로 바뀌어도 3회 판정 일치가 0/5였다. 에이전트의 1.000은 입력을 한 값(ChEMBL 세포 기반 중앙값 등)으로 고정한 결과이며, 입력의 불확실성 범위 안에서 판정이 안정한지는 평가하지 않았다. 결정론 계산기로 IC50 범위에 대한 판정 민감도를 보는 것이 다음 단계다(계획, 미실행).
- 약 4종이라 어떤 비교도 α 0.05에 도달할 수 없다.
- 원샷 팔(planner 역할 1회 호출, effort medium)과 에이전트(노드별 설정)는 호출 구조와 샘플링 설정이 다르다. 차이에는 모델 설정 차이가 섞인다. 감사로그상 모델명은 모두 gpt-6-sol이다.
- 원샷 입력 팔의 지시문은 기억·추정을 권장했다. "프로토콜 값만, 없으면 null"로 지시하면 이 팔은 기권으로 쉽게 일관해질 수 있다. 이 팔의 결과는 실험자가 고른 지시문에 좌우된다.
- 남은 것은 전문가 Gold Set 위에서 저비용 구성의 비열등을 보는 비교다(13.2절 중2).
- 토큰: 원샷 104,928(L1 42,945 + L2 61,983), 원샷 입력 추출 28,800, 에이전트 481,530(12회, 상태 합·감사로그 일치)이다. NLI 필터는 로컬 모델이라 토큰을 쓰지 않았다.

## 9. 검토한 대안

- GPT-6 Astra: 게이트웨이에서 404가 났다(09-11·09-23 실측). 교체 가능한 슬롯만 남겨 뒀다. Astra는 effort none을 받지 않아 클라이언트가 low로 올려 호출한다.
- TypeSafe AI의 Jev(System One, 09-15 공개): 도입하지 않았다. 검토 결과는 아래와 같으며, 불채택 근거 자체를 과학적 타당성과 효율성의 증거로 제시한다.
  - Jev가 약속하는 "타입 오류 0"은 DoseVerdict가 게이트웨이 strict 스키마로 이미 갖추고 있다.
  - 독립 비교의 77-way 분류 정확도에서 Terra 84.0% 대 Jev 78.8%로, Jev가 유의하게 뒤졌다(p=0.029).
  - 벤더가 공개한 sol 74.1% 대 Jev 67.8%는 정답 대비 정확도가 아니라 두 상위 모델 응답과의 **일치율**이다.
  - 확신도는 기권 게이트로 쓸 수 없다. 240 mg 기권은 PK 가정에 따라 답이 갈려서 생기며, 분류기의 확신도로 담을 수 있는 문제가 아니다.
  - 같은 요청을 50번 보냈을 때 서로 다른 답이 15개 나왔다(재현성). SLA도 없다.
  - 대회 쿼터 밖에서 별도로 과금된다.
  - 대신 TypeSafe의 아이디어 가운데 판정 권한을 도구에 묶는 불변식, fail-closed, 호출별 감사로그는 게이트웨이 안에서 구현했다(3.2·3.4·3.5절).
- 프롬프트 캐시: 적중해도 쿼터 차감이 줄지 않아 채택하지 않았다(⑩-b). Batch·Flex는 게이트웨이 지원 여부를 확인하지 않았다.

- 사람 평가는 Human Gate에서 개발자 1인이 승인·기각한 감사로그뿐이다. 외부 자문은 확보하지 못했다.

## 11. 윤리·한계

- **평가셋**: 원·확장 60케이스는 단일 기준 시놉시스의 변형이다. 다약물 30케이스로 약물 3종까지 넓혔지만, 결함 문장은 같은 풀에서 재사용돼 케이스가 독립적이지 않다. DV-505는 합성 입력이다. 원 세트와 확장 세트의 분포가 달라 설정 간 비교는 같은 세트 안에서만 한다. A/B 다중 비교 때문에 원 세트의 최대 개선폭(+0.117)은 과대 추정일 수 있다.
- **채택 기준**: strict와 250자는 사전 규칙상 보류였고, 사후에 정한 비열등성 기준으로 채택했다.
- **외부 타당성**: 실사례 후향 검증은 null이었다(6.8절). 에이전트의 용량 결함 지적은 FDA의 PMR 부과 여부와 관련이 확인되지 않았고, 지적의 정확성은 평가하지 않았다. 공개 출판 자료는 LLM 기억에 들어 있어 누설 없는 후향 검증 입력으로 쓸 수 없다. 누설 차단도 Open Targets 안전성 정보·CT.gov 현재 상태·파이프라인의 약 이름 복원(11/43)을 막지 못했다.
- **특이도**: 결함 없는 프로토콜에서도 실행당 약 6건을 지적한다(6.11절). 이를 줄이는 규칙은 민감도를 크게 떨어뜨려 채택하지 않았다(6.12절). 오경보는 Human Gate에서 사람이 기각해야 한다.
- **구조의 기여**: 같은 모델의 원샷도 결함 문장을 비슷하게 찾는다. 문장 단위 판별력(Youden J)은 필터가 없으면 원샷이, 인용 필터를 맞추면 에이전트가 높았다(6.13절, 사후 점추정). 결함 없는 판에서는 원샷+인용 판정기가 에이전트보다 조용했다(6.13절, 사전 등록). 이를 줄이려던 반박 가능한 Arena는 민감도를 잃어 기각됐다(6.14절). 인용이 원문으로 확인되는 정도의 차이는 사후 분석에서만 나왔고, 판정기가 에이전트 검증기와 같은 모델이라는 한계가 있다.
- **약물 범위**: 이름·성분명 검색으로 매핑 표 밖 약물도 조회한다. 다만 라벨 PK 파서는 실제 라벨 6종의 표현으로만 검증했다. 외부 DB(ChEMBL)가 불안정하면 IC50을 얻지 못해 기권한다(09-26 실행 2/30, 최종 코드 실행 0/30).
- **TCR**: 1차 스크리닝 근사이며 임계값은 잠정이다. 소토라십 같은 공유결합 저해제에는 kinact/K_I 모델이 필요하지만 구현 범위 밖이다.
- **약리 입력**: IC50은 ChEMBL 값 중 표적 키워드로 거른 pool의 세포 기반 중앙값이며, 혈청 단백 보정(serum shift)은 하지 않았다. 설계 몬테카를로의 독성 곡선은 용량군 수에 맞춰 0.05에서 0.70까지 선형으로 늘린 대표 시나리오 1개다(`nodes.py`의 `run_design_oc`). DLT 창 기반이라 누적·저등급 독성은 반영하지 않는다.
- **구조 알림**: 구조 알림으로는 계열 분류만 하고 독성 장기를 추론하지 않는다. 같은 아크릴아마이드 warhead를 가진 오시머티닙 라벨에 간독성 모니터링이 없다는 반례가 있다.
- **NLI**: 수치 패러프레이즈에 약하다. 이런 경우 보류해서 사람에게 넘긴다. 주장과 근거가 모두 한국어면 문자열 대조, 한쪽만 한국어면 다국어 NLI로 검증한다. 교차언어 NLI는 뒷받침하는 근거에도 함의를 낮게 줄 수 있다(예시 ① F02는 원문이 주장을 받치는데도 0.29로 보류됐다).
- **ClinicalTrials.gov**: 설계 구조 비교에만 쓴다. 효능·안전성·규제의 정답으로 쓰지 않는다.
- **사용 맥락**: 의사결정지원 도구이며 자동 제출·자동 승인은 하지 않는다. 사용 맥락은 제출 전 내부 검토 보조다.

## 13. 한계에서 다음 단계로: 발전 가능성과 의의

이 절은 6\~12절에 흩어진 한계를 결과 해석에 미치는 영향에 따라 묶는다. 그다음 한계마다 해소 계획과 판정 기준을 짝짓는다. 13.2의 내용은 모두 계획이며, 아직 실행하지 않았다(중2의 일관성 축소판만 제출 전에 수행했다, 6.15절). 계획에 쓴 임계값도 모두 계획상 기준이다. 13.3의 의의는 이미 확인된 결과에서만 끌어낸다.

### 13.1 결과의 한계와 문제점

한계는 일곱 유형이다. ①\~③은 무엇을 주장할 수 있는지를 제한한다. ④\~⑦은 그 주장이 얼마나 안정적이고 넓게 적용되는지를 제한한다.

| 유형 | 무엇이 | 왜 문제인가 | 결과 해석에 미치는 영향 | 근거 |
|---|---|---|---|---|
| ① 정답의 출처 | 모든 평가가 전문가 라벨 없는 합성 Silver Set 위에 있다. 원·확장 60케이스는 시놉시스 하나의 변형이고, 다약물 30케이스도 같은 결함 풀을 쓴다. 팀에 임상·규제 전문가가 없고 외부 자문도 확보하지 못했다. 사람 평가는 개발자 1인의 Human Gate 기록뿐이다 | "주입한 문장은 결함이고 기준 문장은 결함이 아니다"라는 가정이 정답을 대신한다. 케이스끼리도 독립적이지 않다 | 수치는 주입 결함을 다시 찾는 내부 타당도다. 특이도는 하한이다. verified는 인용이 원문과 맞는다는 뜻이고, 지적이 타당하다는 뜻은 아니다. 지적 정확성과 수정안의 질은 평가하지 않았다 | 4, 6.11, 10절 |
| ② 외부 타당성 | 승인 전 1상 초록 43건 후향 검증은 null이었다(S1 AUROC 0.440 [0.270, 0.621]). 모델은 가린 약을 42\~43/43 재식별했고, 11/43에서는 약 이름을 복원해 검색에 썼다 | 실제 약에서 판별력이 있다는 증거가 없다. 공개 출판 자료는 모델 기억과 분리되지 않는다 | "실제 용량 위험을 가려낸다"고 주장할 수 없다. 공개 자료로 후향 검증을 되풀이해도 이 문제는 풀리지 않는다 | 6.8절 |
| ③ 구조의 기여 | 같은 모델 원샷과의 사전 등록 판정은 "차이 확인 안 됨"이었다(grounded −0.092 [−0.208, +0.021]). 이 비교는 원샷에 유리한 조건이었다(에이전트만 결함 출처 조항 hold-out). ablation에서도 구성요소 기여는 측정되지 않았다. 결함 없는 판에서는 원샷+인용 판정기가 더 조용했다(사전 등록). 지적 문장의 반복 일관성도 사전 등록 판정이 '이 시놉시스 4종에서 차이 확인 안 됨'이었고, 방향은 에이전트가 낮았다(−0.059) | 에이전트는 원샷보다 토큰을 약 8배 쓴다. 그만큼 탐지가 나아진다는 증거는 없다 | 남는 몫은 원문 인용과 도구 계산 기반 기권이다. 그러나 인용 차이는 사후 분석이고 판정기가 에이전트에 유리하다. 기권 평가에는 순환성 단서가 붙는다 | 6.1, 6.9, 6.10, 6.13, 6.15절 |
| ④ 오지적과 민감도의 교환 | 결함 없는 판에서 실행당 defect finding 6.42, 문장 특이도 0.64였다. 지적을 줄이려던 두 시도(보정 규칙, 반박 Arena)는 판별력을 잃어 사전 규칙대로 기각했다 | 오경보를 Human Gate에서 사람이 하나씩 기각해야 한다. 그 비용은 재지 않았다 | 현재 기본값은 민감도를 우선한 운영점이다. 이 선택이 현장에서 이득인지는 검증하지 않았다 | 6.11, 6.12, 6.14절 |
| ⑤ 측정 안정성과 사후 결정 | 같은 설정을 반복하자 grounded가 0.067 흔들렸다. 재실행은 기각 판정에만 했다. 사전 계획의 안정성 감사(15케이스 × 2회)는 하지 않았다. lean 기준선은 1회 실행이다. strict·250자 채택과 gpt-6-sol 유지는 사후 결정이다. 확장 40케이스는 최종 코드로 다시 돌리지 않았다 | 케이스 단위 부트스트랩 CI는 실행 간 변동을 담지 못한다 | 반복으로 확인한 것은 토큰 절감과 검증 통과율 상승뿐이다. grounded 차이는 방향만 읽는다 | 5.2, 6.2, 6.3절 |
| ⑥ 약리 모형 | TCR은 선형 1구획과 ChEMBL 세포 기반 IC50 중앙값에 기댄 스크리닝 근사다. 혈청 단백 보정이 없다. 공유결합 저해제에 필요한 kinact/K_I 모델은 구현하지 않았다. 임계값은 잠정이다. 포화 의심(>10)은 정의만 있고 결과에 표시하지 않는다. 독성 곡선은 대표 시나리오 1개다. 라벨 PK 파서는 라벨 6종으로만 검증했다. 설계·표본수 수치 주장의 자동 차단은 없다 | 커버와 기권 판정이 모형 가정에 달려 있다 | 기권이 동작한다는 것은 확인했다. 그러나 판정 기준이 옳다는 근거는 아니다. TCR 커버는 효능을 예측하지 않는다(240 mg ORR 사례) | 1, 3.1, 6.4, 6.5, 11절 |
| ⑦ 근거 코퍼스·검증기·운영 | 코퍼스 396절의 59%가 ICH E6이다. 식약처 근거는 1443-01의 11절뿐이다. 목록에만 있고 본문을 색인하지 않은 문서가 3종이다. 교차언어 NLI는 원문이 받치는 주장도 보류했다(예시 ① F02, 함의 0.29). 배포본(CPU)은 근거 재선택이 꺼져 있다. 라이브 83초는 1회 측정이다. 재계획 트리거 12종 중 8종은 평가에서 0건이었다 | 한국 규제 근거가 얇다. 평가 수치가 배포본에서 그대로 나온다는 보장이 없다 | 한·미 동시 검토의 한국 쪽은 시연 수준이다. 자율성 주장은 평가 세트에서 발동한 4종까지다. 3종은 적대 데모, 5종은 단위 테스트 수준이다 | 3.2, 3.3, 6.3, 7, 8.2절 |

종합하면 이 한계들이 남기는 주장의 범위는 좁다. 정답을 맞힌다는 주장, 원샷보다 낫다는 주장, 실제 약에서 위험을 가려낸다는 주장은 할 수 없다. 가장 큰 공백은 ①과 ②다. 이 둘은 모델이나 프롬프트를 고쳐서는 풀리지 않는다. 평가의 정답(전문가 라벨)과 입력(기억 오염 없는 문서)을 바꿔야 풀린다. ③과 ④도 정답이 바뀌어야 다시 판정할 수 있다. 13.2의 순서는 이 판단에서 나왔다.

### 13.2 향후 발전 로드맵(계획)

로드맵은 세 원칙을 따른다.

- 모든 단계는 실행 전에 판정 규칙과 반증 조건(13.4절)을 커밋한다. 6.8\~6.15절의 사전 등록 방식을 그대로 쓴다.

- 순서는 먼저 지금 수치의 안정성을 확인하고(단기), 다음으로 정답과 입력을 바꾸고(중기), 그 뒤 실제 검토 흐름 안에서 시험한다(장기). 지원 범위 확장은 맨 마지막이다.

단계 이름은 단1\~단5, 중1\~중6, 장1\~장3으로 적는다. 후향 검증 점수 S1(6.8절)과 섞이지 않게 하려는 것이다.

#### 중기: 발표 이후 약 6개월(외부 협력 확보가 전제)

### 13.3 의의(확인된 결과에 한함)

항목마다 근거 결과와 경계를 함께 적는다.

- 수치 판정을 도구에 묶었다. 판정이 갈리면 멈추고, 갈리지 않으면 멈추지 않았다.
  - 근거: 소토라십 240 mg은 지표와 PK 가정에 따라 판정이 갈려 결론 대신 반복투여 PK를 요청했다(6.5절). 다약물 30케이스에서 약리 축이 30/30 계산됐다. 지표에 따라 판정이 갈린 아다그라십·DV-505는 기권했고, 로를라티닙은 기권하지 않았다(6.4절).
  - 경계: TCR은 스크리닝 근사이고 효능을 예측하지 않는다(6.5절). DV-505는 합성 입력이며, 실제 IND 프로토콜로 검증하지 않았다(6.4절).
- 입력이 비면 전형값으로 채우지 않았다.
  - 근거: 후향 검증 43건 모두에서 F00이 입력 부족으로 기권했다(6.8절). 다만 라벨 차단과 마스킹으로 입력을 지운 조건의 결과라, 기권 규칙이 의도대로 동작했다는 것만 보여 준다. 근거 없는 400 mg 주장에는 추정값을 만들지 않고 보류했다(7절).
  - 대조: 사전 등록 조건 A에서는 기권 선택지만 줘도 도구 없는 모델이 확정 판정을 내지 않았다(0.000, 6.10절). 차이는 추정을 강요할 때의 재현성에서만 보였다. 사전 등록 재측정에서 3회 판정이 모두 같은 용량군은 도구 없는 원샷 0.650, 원샷이 고른 입력에 결정론 계산기를 붙인 팔 0.700, 에이전트 1.000이었다. 원샷 입력 팔은 IC50을 회차마다 다시 골랐다(6.15절). 기술 통계이며(판정값 분포와 3회 모두 답 누락(missing)이거나 자료 없음(cannot_assess)인 용량군 0은 6.15절), 에이전트 값에는 이미 관측됐고 도구 정답과 같은 계산 경로라는 순환성 단서가 붙는다. 이 재현성은 결정론 조회 규약의 성질이고 LLM 에이전트에 고유하다는 근거는 아니다(규칙 조회 팔 미실행). 6.10절 사후 A′의 26.7%는 다른 실행이며, 같은 3종의 재측정 0.533으로 재현되지 않았다.
- 인용 경로는 원문을 바꾸지 않는다.
  - 근거: 근거 풀의 규제 조항 인용문은 1,308/1,308건이 코퍼스 원문이다(6.9절).
  - 경계: 검색 원문을 그대로 붙이도록 설계했으므로 설계상 거의 자동으로 나오는 값이다. 확인한 것은 인용 경로에 변형이 없다는 사실뿐이다. 그 위에 LLM이 쓴 근거 문장의 원문 확인 차이는 사후 분석이고, 판정기가 에이전트에 유리하다(6.9절).
- 검증 통과율을 낮추지 않고 자원을 줄였다.
  - 근거: 09-11 기준선보다 토큰이 −10.4%, 검증 통과율이 +0.044 [+0.012, +0.071]였다. 최종 코드 2회 모두 CI가 0을 벗어났다(6.3절). 쿼터를 줄이는 레버는 effort가 아니라 입력 길이였고, 프롬프트 캐시는 쿼터 차감을 줄이지 않았다(6.7절).
  - 경계: lean 기준선은 1회 실행이다. 검증 통과율은 인용 일치율이지 지적 품질 지표가 아니다.
- 실패가 드러나도록 설계했다.
  - 근거: 배포본의 규제 검색 결함은 실패한 도구 호출을 관측값으로 남긴 덕에 찾았다(8.3절). 핵심 노드의 구조화 출력이 실패하면 "결함 없음"이 아니라 "결론 없음"으로 처리한다(3.4절). 모든 LLM 호출의 모델·effort·프롬프트 해시·usage를 감사로그에 남기고, 최종 승인은 사람만 한다(3.1·3.5절).
  - 경계: 검토 이력을 남겨야 하는 환경에 맞는 성질일 뿐, 규제 요건을 충족한다는 뜻은 아니다(장2).
- LLM 규제 검토 도구 평가에 쓸 방법론적 교훈 네 가지를 남겼다.
  - 같은 모델 원샷이 필수 대조군이다. 원샷과 비교하지 않았다면 구조의 탐지 기여를 과대 주장했을 것이다(6.9절).
  - 공개 출판 자료는 누설 없는 후향 입력이 되지 못한다. 가린 초록이 43/43 재식별됐고, SMILES·표적·기전을 빼도 42/43이었다. 공개 자료로 후향 검증을 설계하려면 재식별 탐침을 먼저 돌려야 한다(6.8절).
  - 케이스 단위 CI만으로 설정을 채택하면 안 된다. 같은 설정 반복에서 grounded가 0.067 흔들렸고, 1회 실행의 기각 판정이 재실행에서 보류로 바뀌었다(6.3절).
  - 현재 파이프라인에서 오지적을 줄이면 판별력도 함께 떨어졌다. 사전 등록 A/B 두 번에서 그랬다(6.12·6.14절). 특이도를 사람 단계에 맡긴 설계는 이 결과에 근거한다.

모든 수치는 커밋된 결과에서 토큰 0으로 다시 만들 수 있다(12절). 이 의의는 "더 많이 찾는다"나 "더 정확하다"가 아니다. 근거가 얇을 때 멈추고 출처를 남기는 행동과, 그 행동을 불리한 결과까지 포함해 검증 가능하게 남기는 절차가 확인됐다는 뜻이다.

의의로 주장하지 않는 것은 다섯 가지다. 원샷 대비 우위, 실제 약에서의 판별력, 인용 일치 차이(사후·판정기 비대칭), 도구 판정의 정확도(순환성), 지적의 반복 일관성(사전 등록 판정 '이 시놉시스 4종에서 차이 확인 안 됨', −0.059, 약 4종 중 3종에서 에이전트가 덜 일관, 6.15절)이다.

아래 결과가 나오면 방향을 접거나 바꾼다. 이 조건도 단3에서 각 단계의 사전 등록 문서와 함께 커밋한다.

## 14. 결론

DoseVerdict는 프로토콜의 용량 근거를 도구로 계산해 규제 원문에 묶어 내놓고, 판정이 갈리면 기권하며, 승인은 사람에게 남기는 검토 보조 에이전트다. 내세울 수 있는 것은 '더 많이 찾는다'도 '더 잘 계산한다'도 아니다.

#### 확인한 것

- 09-11 배포 기본값보다 토큰을 10.4% 적게 쓰면서 검증 통과율이 +0.044 [+0.012, +0.071] 높았다. 같은 설정을 두 번 돌려도 유지됐다. 다만 lean 기준선은 1회 실행이다(6.3절).
- 결함을 넣은 합성 세트에서 결함 문장은 93\~98%, 기준 문장은 74\~81%를 구별했다. Youden J는 0.67\~0.76이다(6.11절). 특이도는 하한이며, 같은 규칙에서 필터 없는 원샷의 J는 0.85\~0.86으로 더 높았다(사후, 6.13절).
- 다약물 30케이스에서 약리 축이 모두 끝까지 돌았다. 판정이 지표에 따라 갈린 아다그라십과 DV-505에서는 기권했다. 결함 문장은 원 세트와 같은 풀에서 왔다(6.4절).

#### 확인하지 못한 것

- 에이전트 구조가 탐지를 낫게 한다는 것. 같은 모델 원샷과의 사전 등록 판정은 차이 없음이었다(grounded −0.092 [−0.208, +0.021]). ablation에서도 구성요소 기여는 측정되지 않았다(6.1·6.9절).
- 실제 약에서의 판별력. 승인 전 1상 초록 43건 모두에서 결함을 지적해 PMR 부과 약을 가르지 못했다(AUROC 0.440 [0.270, 0.621]). 입력은 모델 기억과 분리되지 않았다(6.8절).
- 결함 없는 판에서의 조용함. 실행당 defect finding은 6.42였다. 지적 기준 문장은 원샷+인용 판정기 6.0, 에이전트 8.0으로 원샷이 더 조용했다. 오지적을 줄이려던 두 시도는 민감도를 떨어뜨려 기각했다(6.11\~6.14절).
- 같은 입력에서 지적이 더 일관된다는 것. 지적 문장 집합의 3회 Jaccard는 에이전트 0.687, 원샷 0.746이었고, 사전 등록 판정은 '이 시놉시스 4종에서 차이 확인 안 됨'이었다. 약 4종 중 3종에서 에이전트가 낮았다(6.15절).

#### 사후 분석·기술 통계에서만 보인 것

- 근거 문장을 인용 문서의 조항과 대조하면 에이전트 94\~98%, 원샷 55\~77%가 확인됐다. 판정기가 에이전트에 유리한 한계가 있다(6.9절).
- 도구 없는 같은 모델은 추정을 요구받으면 3회 판정 일치가 26.7%였다. 이 사후값은 정답을 쓰지 않는 모델 내부 재현성 지표이며, 같은 지시문·같은 3종의 사전 등록 재측정에서 0.533으로 재현되지 않았다. 재측정의 용량군 판정 일치(사전 등록 실행이지만 판정 문구 없는 기술 통계)는 원샷 4약 0.650, 원샷 입력 + 계산기 0.700, 에이전트 1.000이었다(판정값 분포는 6.15절). 에이전트 1.000은 이미 관측된 값이고 도구 정답과 같은 계산 경로라 순환적이며, 결정론 조회 규약의 성질일 뿐 LLM 에이전트가 필요하다는 근거가 아니다(규칙 조회 팔 미실행, 6.15절).
- 원 20 문장 단위 판별력의 순서는 비교 조건에 따라 갈렸다(6.13절).

그 밖의 단서도 해당 절에 적었다. 같은 설정의 반복 실행에서 grounded가 0.067 흔들렸다. 1회 실행 회귀 판정 하나는 재실행으로 기각에서 보류로 바뀌었다. 재실행은 기각 판정에만 했고, 사전 계획의 안정성 감사는 수행하지 않았다. 확장 세트의 grounded 개선은 유의하지 않았다. strict·250자는 사후 기준으로 채택했다. 배포본에는 검색 결함이 있었다(8.3절). 모든 평가는 전문가 라벨이 없는 합성 세트 위에 있다.

다음 단계와 반증 조건은 13.2·13.4절에 적었다. 중2의 일관성 축소판(6.15절)을 빼면 모두 계획이며 아직 실행하지 않았다.
