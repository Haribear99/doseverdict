# 반복 일관성 비교 — 사전 등록 (2026-10-01, 실행 전 커밋)

## 질문
같은 입력이면 같은 판정이 나오는가. 지금 쓰는 근거는 사후 분석 하나다. 도구 없는 모델(abstain_eval 사후 조건 A′)은 같은 약·용량을 3번 판정했을 때 판정이 모두 같은 용량군이 0.267이었다(`app/eval/abstain_eval.py::post_hoc_lines`). 사전 등록이 없던 값이므로 주장 근거로 쓸 수 없다.

이 문서는 그 질문을 사전 등록 지표로 작게 다시 잰다. 덱 12장(10-01 재구성 전에는 11장)과 기술서 13.2절 둘째 항목에 계획으로 적은 3팔 비교의 축소판이다. 다만 아래 '이미 본 것' 때문에 하나의 시스템을 세 팔로 비교하는 설계가 아니라 **지표별 비교**로 정리했다.
- L1(용량군 판정): 원샷 / 원샷 입력 + 결정론 계산기 / 에이전트
- L2(지적한 시놉시스 문장): 원샷 / 원샷 + NLI 필터(민감도) / 에이전트

"원샷 + 인용 판정기 + 도구 기권"이라는 하나의 시스템은 어느 지표에서도 실행되지 않는다. L1의 둘째 팔은 입력 추출 + 계산기만 쓰고 판정기를 쓰지 않는다. L2의 둘째 팔은 원샷 출력에 NLI 필터만 건다.

## 이미 본 것(블라인드 아님)
- 시놉시스 4종은 팀이 만들었고 여러 평가에서 이미 썼다.
- **원샷 L1**: 반복 판정 일관성 0.267(사후 A′)과 회차별 IC50 재선택(3~9배)을 이미 봤다. 그래서 `results/abstain_raw_mem.json`은 재사용하지 않고 새로 3회 실행한다.
- **에이전트 L1은 이미 관측됐다.** 실행 전 기존 상태(`results/states/*/`)의 `TCR(` 근거를 `_ROW`로 파싱해 확인했다(토큰 0).
  - 소토라십 AX1-001: 29개 실행(full·lean·lean_v3·lean_v3b·no_arena 등) 중 TCR 근거가 있는 27개에서 5개 용량군 판정이 모두 같다(180~720 mg indeterminate, 960 mg covered). TCR 근거가 없는 2개는 no_calc(계산 절제)와 lean_refute_pilot(ChEMBL potency 도구 실패)다.
  - 아다그라십·로를라티닙·DV-505: lean_mdrug·lean_mdrug3·lean_mdrug_refute 3회에서 판정이 모두 같다.
  - 입력값(CL/F, t½, τ, f_u, IC50, MW)도 실행마다 같다(코드 버전별 표기 '5'/'5.0' 차이와 옛 형식의 τ 미표기만 다르다).
  - 다만 lean_d3·lean_refute·lean_strict에서는 에이전트가 시놉시스에 없는 200 mg 행을 추가로 계산했다(용량 추출 변동).
  - 입력이 openFDA 라벨·ChEMBL 중앙값·RDKit MW·프로토콜 보고값에서 결정론적으로 정해지므로(`nodes.py` `_pk_inputs`, `run_exposure_dose`), 에이전트 L1은 인프라 실패가 없으면 사실상 1.000이다.
- **L2도 일부 이미 봤다.** 이 사전 등록을 고치면서 기존 상태로 계산한 값이다(사후, 토큰 0).
  - 결함을 고친 시놉시스(`app/demo/*_synopsis_fixed.md`, 이번 표본과 **다른 문서**)에서 약별 3회 쌍별 Jaccard는 원샷(`states/clean_oneshot`) 0.630·0.518·0.504·0.540, 에이전트 lean(`states/clean_base`) 0.389·0.494·0.417·0.370이다(소토라십·아다그라십·로를라티닙·DV-505 순서). **네 약 모두 에이전트가 낮았다.**
  - 이번 표본(결함 시놉시스)에서 설정·코드 버전이 다른 에이전트 실행 사이의 Jaccard는 0.50~0.83이다(소토라십 lean_v3 대 lean_v3b 0.727; 아다그라십 0.50~0.75; 로를라티닙 0.50~0.57; DV-505 0.69~0.83). 같은 설정 3회가 아니므로 이번 값의 추정치가 아니다.
  - 따라서 1차 비교의 방향은 실행 전에 완전히 모르는 상태가 아니다. 앞의 관측은 에이전트 쪽이 불리한 방향이다. 결과가 어느 쪽이든 이 사실과 함께 보고한다.

## 팔
원샷 호출은 모두 `GatewayClient(audit_path=<저장소>/logs/eval_runs.jsonl).respond("planner", …, reasoning_effort="medium")`로 한다. 도구와 검색은 쓰지 않는다. L1 호출의 purpose는 `consistency:<약>:<l1_oneshot|l1_inputs>:<회차>`다.

| 지표 | 팔 | 내용 |
|---|---|---|
| L1 | 원샷(도구 없음) | `abstain_eval`의 `INSTR_MEM` + `prompt(it, "A")` + `SCHEMA`를 새로 3회 보낸다(기억·추정 사용 권장). 모델이 낸 용량군별 `verdict`를 쓴다 |
| L1 | 원샷 입력 + 결정론 계산기 | 같은 입력 텍스트 `prompt(it, "A")`를 보내되, 모델은 PK 입력만 고른다. 입력은 CL/F(L/h), t½(h), τ(h), f_u, IC50(nM), MW이고 각각 값과 출처(`protocol`/`prior_knowledge`/`assumption`)를 단다. 지시문 `consistency.INSTR_INPUTS`는 `INSTR_MEM`과 같은 취지로 기억·추정을 권장하고, 판정은 직접 하지 말라고 한다. 고른 입력을 `app/tools/pharmacology.py::tcr_three_metrics`에 넣고 `TOOL2LABEL`로 판정한다(`abstain_metric_dependent` → `indeterminate`) |
| L1 | 에이전트 | 아래 에이전트 실행의 상태 evidence 중 `kind == "calculation"`이고 `TCR(`로 시작하는 첫 quote를 `abstain_eval._ROW`로 파싱한다(`items()`와 같은 규칙) |
| L2 | 원샷(원 출력) | `run_eval.run_oneshot(gc, synopsis)`와 같은 호출(같은 프롬프트·purpose `eval_oneshot`)의 finding 전부(필터 없음). `span` 필드. 응답 원문을 남기는 얇은 래퍼(`consistency._Capture`)로 파싱 성공 여부를 기록한다 |
| L2 | 원샷 + NLI 필터(**민감도**) | 위와 **같은 원샷 출력 12회**를 `oneshot._support(f, bd, "nli")`로 거른 finding(`hybrid.py`와 같은 방식). 원샷 집합의 부분집합이라 1차와 독립된 증거가 아니다 |
| L2 | 에이전트 | defect finding의 `protocol_span.text`. F00(요약)과 결정론 버전 점검 finding(`V**`, `findings.py`)은 LLM 판정이 아니므로 뺀다 |

에이전트 실행: `app.agents.graph.run_until_gate(synopsis, run_id=f"consistency-agent-{drug}-{rep}"[+"-retry<k>"], ablate=[], reviewers=["regulatory"], holdout_chunk_ids=<gold 케이스 값>)`. `run_eval._GRAPH_CONFIGS["lean"]`과 같은 기본 배포 설정이다. `DV_AUDIT_LOG`가 비어 있으면 저장소 `logs/eval_runs.jsonl`로 지정한다.

### 실행 환경 기록
- 모든 상태 파일(원샷 포함)에 실행 시점의 `DV_*` 환경변수 전부와 `_rerank_enabled()`를 저장한다(원샷은 `consistency.env`, 에이전트는 `scratch.consistency.env`). `DV_BLIND_LABEL`, `DV_ASOF_DATE`, `DV_NLI_*`, `DV_LLM_TIMEOUT`, `DV_MODEL_*`, `DV_NODE_MODEL_*`, `DV_EFFORT_*`가 포함된다.
- `report`는 kind별로 서로 다른 환경 조합 수를 내고, 2개 이상이면 경고한다.
- 실행 전 체크: 셸과 `.env`에 `DV_BLIND_LABEL`, `DV_ASOF_DATE`가 설정돼 있지 않은지 확인한다(값은 출력하지 않고 설정 여부만).

### 인프라 실패와 재실행(사전 고정)
- **인프라 실패 정의**
  - 원샷(L1 원샷·입력 추출·L2 원샷): 응답 JSON 파싱 실패(L2는 `findings` 배열이 없는 경우 포함). 정상 파싱된 빈 목록(`findings: []`)은 실패가 아니다.
  - 에이전트: `scratch.llm_failures`가 하나라도 있거나(노드 구조화 출력 실패, `terminal_status == "no_conclusion"`·`llm_output_failure`를 포함), `replan_events`에 `trigger == "tool_failure"`가 있는 경우(ChEMBL·openFDA 재시도 후 실패). openFDA 404(미승인 후보물질)는 예상된 결과라 여기에 들지 않는다.
- 인프라 실패 시도는 표본으로 쓰지 않고 `<kind>/_failed/<drug>_<rep>_<k>_<ts>.json`에 격리 저장한 뒤 같은 회차를 다시 돌린다. 에이전트 재실행의 run_id는 `-retry<k>` 접미사를 붙인다.
- 회차당 재실행은 최대 2회다. 세 번째 시도도 인프라 실패면 그 결과를 표본으로 쓰고 `infra_failure_final`로 표시한다. 이 회차는 L1에서는 저장된 판정 그대로(근거가 없으면 `missing`), L2에서는 **missing**(그 회차가 낀 쌍의 Jaccard = 0, 불일치)으로 센다.
- 쿼터 소진(`QuotaExhausted`)·네트워크 재시도 초과 같은 예외는 상태를 쓰지 않고 멈춘다. 같은 명령으로 재개하면 그 회차를 처음부터 다시 돌린다(재실행 횟수에 넣지 않는다).
- 재실행 횟수와 실행별 `terminal_status`·`llm_failures` 수를 `report`의 '실행별 상태' 표에 낸다. 결과를 본 뒤의 추가 재실행은 하지 않는다.

### 판정값 규칙(사전 고정)
- 판정값은 `covered`, `not_covered`, `indeterminate`, `cannot_assess`, `missing` 다섯 가지다.
- **L1 원샷**: 판정 문자열은 공백 제거·소문자화한 뒤 앞의 네 값 중 하나가 아니면 `missing`이다. 답에 없는 용량군, dict가 아닌 항목, JSON 파싱 실패도 `missing`이다.
- **L1 원샷 입력 + 계산기**
  - 파싱 실패는 `missing`이다.
  - 입력 6개 중 하나라도 null, 숫자로 읽히지 않는 값, 0 이하, 또는 f_u > 1이면 해당 약·회차의 모든 용량군을 `cannot_assess`로 둔다. 도구가 결론을 내지 않는 것이 이 팔의 기권이다.
  - 숫자와 숫자만 있는 문자열("26.2")은 숫자로 읽는다. **단위가 붙은 문자열("26.2 L/h")은 읽지 않는다**(`cannot_assess`). 단위 환산을 추측하지 않기 위해서다. 도구 오류도 `cannot_assess`다.
  - 판정은 `report`에서 저장된 입력으로 결정론적으로 다시 계산한다(토큰 0).
- **L1 에이전트**: TCR 계산 근거가 없는 실행은 그 실행의 모든 용량군이 `missing`이다. 입력 누락으로 도구가 판정을 보류한 경우도 여기에 들어간다. 계산 표에 없는 용량군도 `missing`이다.

## 지표(사전 고정)
- **L2 = 약별 3회 실행의 쌍별 Jaccard 평균(3쌍).** 집합은 지적된 시놉시스 문장의 번호다. 문장 분할은 `specificity.sentences`, 겹침은 `specificity.flagged`(`run_eval.matches`)로 정한다.
  - 두 회차 모두 지적한 문장이 없으면 그 쌍의 Jaccard는 1.0이다. 최종 인프라 실패 회차가 낀 쌍은 0이다. 전체 L2는 약별 값의 평균이다.
  - 함께 싣는 것: 회차별 집합 크기, 빈 집합 쌍 수, 최종 실패 회차 수.
  - 2차: 빈 집합 쌍을 뺀 L2(남는 쌍이 없는 약은 빠진다).
  - `matches`는 span이 문장에 포함되면 겹침으로 친다. 짧은 span은 여러 문장을 지적한 것으로 잡힐 수 있고, Jaccard는 집합 크기와 span 길이에 기계적으로 좌우된다. 집합 크기를 같이 보는 이유다.
- **L1 = 용량군(약×용량) 중 3회 판정이 모두 같은 비율.** 분모는 3회가 다 끝난 약의 용량군이다. 약별 (일치 수, 용량군 수)를 합산한 비율이다(`consistency.l1_per_drug`, `_l1`).
  - `missing`도 하나의 판정값으로 친다. 3회 모두면 일치, 한 번만 있어도 불일치다.
  - 이 규칙은 출력을 일관되게 못 내는 팔을 1.000으로 만들 수 있다. 그래서 L1을 인용할 때는 팔별 판정값 분포(5값 개수)와 "3회 모두 `missing`·`cannot_assess`인 용량군 수"를 반드시 같이 싣는다.
  - 2차: 어느 회차든 `missing`이 있는 용량군을 뺀 L1, 약별 L1의 단순 평균(합산 비율은 용량군이 많은 약에 가중이 커진다).
- **입력 재현(L1에서 정보가 있는 지표, 기술용)**
  - 원샷 입력 + 계산기: 약별로 3회가 고른 입력 6개가 모두 같은가.
  - 에이전트: 약별로 3회가 확보한 입력 6개(CL/F, t½, τ, f_u, IC50, MW; 숫자로 정규화)가 모두 같은가, 그리고 TCR을 계산한 **용량 집합**(items() 밖 용량 포함)이 모두 같은가. 시놉시스에 없는 용량 행 추가는 여기서 드러난다.

## 비교와 판정(사전 고정)
- **1차 비교는 하나다: L2 (에이전트 − 원샷).** 1차가 하나라 다중 비교 보정은 없다(α = 0.05, 양측).
- **민감도**: L2 (에이전트 − 원샷 + NLI 필터). 같은 원샷 출력의 부분집합이라 판정 문구를 만들지 않는다.
- **기술 비교(판정 문구 없음)**: L1 (에이전트 − 원샷), (에이전트 − 원샷 입력 + 계산기), (원샷 입력 + 계산기 − 원샷). 에이전트가 낀 L1 비교는 이미 관측된 결과의 재현이라 1차에서 뺐다.
- **추론**: 약 단위 정확 부호 뒤집기 검정(`consistency.sign_flip`). 약별 차이 4개의 부호를 바꾼 2⁴ = 16가지를 전부 열거해, 차이 평균의 절댓값이 관측값 이상인 비율을 양측 p로 쓴다.
  - **약 4종에서는 가능한 최소 양측 p가 2/16 = 0.125다. 따라서 α = 0.05에서 어떤 결과도 유의할 수 없고, 1차 판정 문구는 실행 전부터 "차이 확인 안 됨"으로 정해져 있다.** 이것을 숨기지 않는다.
  - 결과는 **방향 일치 수(k/4: 차이가 양수인 약, 음수인 약, 0인 약)**와 **효과 크기(약별 차이와 평균 차이)**로 읽는다.
  - 기술용으로 약 단위 쌍대 부트스트랩 95% CI를 병기한다. 약 4종의 순서 있는 재표본 4⁴ = 256개를 같은 가중치로 정확 열거한다(몬테카를로 아님, seed 불필요). 분위 위치는 `hybrid._diff`와 같다. 어느 약이든 한 약만 4번 뽑히는 재표본이 4/256 = 1.56%라 CI 끝은 가장 극단적인 약 하나에 좌우된다. CI로 판정 문구를 만들지 않는다.
  - L1 차이는 재추출한 약들의 용량군을 합산한 비율로, L2 차이는 약별 Jaccard 평균의 평균으로 계산한다.
- **판정 문구(1차만)**: 정확 검정 p ≤ 0.05이고 차이 > 0 → **"이 시놉시스 4종에서 에이전트가 같은 입력에 더 일관된 판정(지적 문장 집합)을 낸다"**, p ≤ 0.05이고 차이 < 0 → **"이 시놉시스 4종에서 에이전트가 덜 일관된 판정(지적 문장 집합)을 낸다"**, 그 외 → **"이 시놉시스 4종에서 차이 확인 안 됨"**. 범위 한정어("이 시놉시스 4종에서")를 떼고 인용하지 않는다.
- **완료 조건**: 1차는 `oneshot`과 `agent` 상태가 각각 12/12일 때만 판정 문구를 낸다. 그 전에는 "미완"으로 표시하고, 끝난 실행만으로 낸 중간값은 중간값이라고 적는다.

## 결과별 보고 방침(사전 고정)
- **어느 결과든 기술서와 덱에 그대로 싣는다.** 1차 판정 문구는 위 세 가지 중 하나를 그대로 쓰고, 방향 일치 수와 효과 크기를 함께 쓴다.
- 실행이 마감(2026-10-02 16:00) 전에 다 끝나지 않으면 n을 줄여 결론 내지 않는다. 완료 개수와 함께 "미완"으로 보고한다.
- "더 일관된다"는 방향이 나와도 "더 정확하다"로 쓰지 않는다(한계 1).
- 에이전트가 낀 L1 수치는 "(한계 3: 에이전트 L1은 이미 관측됐고 도구 정답과 같은 계산 경로)" 단서와 함께만 인용한다. L1에서 정보가 있는 비교는 '원샷 입력 + 계산기'와 에이전트의 **입력 재현**이다.
- 유의하지 않은 차이를 동등성으로 읽지 않는다. 동등성 마진을 사전에 정하지 않았으므로 "계산기만 붙여도 일관된다" 같은 동등성 주장은 하지 않는다.
- 판정 문구는 L2 하나에만 있다. L1과 L2를 합친 종합 문구("에이전트가 더 일관된다" 일반)는 만들지 않는다.

## 비용(사전 기재)
- 팔별 토큰을 보고한다.
  - 원샷 = L1 원샷 + L2 원샷(격리된 실패 시도 포함)
  - 원샷 입력 + 계산기 = L1 입력 추출(격리 포함). L2 NLI 필터는 원샷 L2 출력을 공유하고 로컬 NLI라 추가 토큰이 없다.
  - 에이전트 = **감사로그**에서 purpose가 `consistency-agent-`로 시작하는 호출의 usage 합(재시도·중단분 포함)이 1차 값이다. 상태 `budget.used_tokens` 합을 병기하고, 차이는 "중단·재시도분"으로 표기한다.
- 감사로그 교차 확인: purpose `consistency:<약>:l1_oneshot:`과 `consistency:<약>:l1_inputs:`의 usage 합계를 따로 낸다. L2 원샷은 `run_eval.run_oneshot`의 고정 purpose(`eval_oneshot`)를 그대로 써서(모델 선택이 purpose에 따라 달라질 수 있으므로 바꾸지 않는다) 감사로그에서 가려낼 수 없다. 그래서 상태에 기록한 호출 사용량만 쓴다.
- 감사로그 경로는 저장소 루트 기준 절대경로(`<저장소>/logs/eval_runs.jsonl`)다.
- 추정치(기존 실행 기준)
  - L1 원샷 약 3.7k/호출(사후 A′ 12회 44k)
  - L2 원샷 약 5k/회(clean_oneshot 12회 평균 5,054)
  - 에이전트 약 40k/회(lean_v3·lean_mdrug3 해당 케이스 36.8k~41.5k)
  - 합계 약 0.6M 토큰(에이전트 약 0.48M). 인프라 실패 재실행이 최대로 나면 약 1.8M.

## 한계(사전 인정)
1. **일관성은 정확성이 아니다.** 매번 같은 틀린 판정도 L1 = 1.000이다.
2. **계산기가 결정론적이다.** 그래서 '원샷 입력 + 계산기'와 에이전트의 L1 변동은 입력 선택에서만 나온다. 이 실험이 L1에서 가르는 것은 '계산기가 있는가'가 아니라 '입력을 어떤 규약으로 확보하는가'다(원샷 입력: 모델 기억·추정; 에이전트: PK는 라벨 → 프로토콜, IC50은 ChEMBL → 프로토콜 순서의 고정 규약, 없으면 전형값으로 채우지 않고 보류).
3. **에이전트 L1은 이미 관측됐고 순환적이다.** 도구 정답(`items()`)을 정의한 것과 같은 계산 경로다. 그래서 1차 판정에서 뺐다.
4. 시놉시스는 이미 본 문서다(블라인드 아님). L2도 다른 문서·다른 설정에서 방향을 이미 봤다('이미 본 것').
5. **약 4종으로 n이 작다.** 정확 검정으로는 어떤 결과도 α = 0.05에 도달할 수 없다. 방향 일치 수와 효과 크기만 읽는다.
6. 같은 문서를 3회 돌린 것이라 회차는 독립 표본이 아니다. 이 평가는 바로 그 반복 간 변동을 재는 것이다.
7. **'원샷 입력 + 계산기'의 지시문이 결과 방향을 정할 수 있다.** 지시문은 기억·추정을 권장한다("prefer giving a value over null"). 사후 A′(`INSTR_MEM`)과 같은 취지로 맞춘 것이다. 반대로 "프로토콜 값만 쓰고 없으면 null"로 지시하면 이 팔은 기권(`cannot_assess`)으로 쉽게 일관해질 수 있다. 즉 이 팔의 L1은 실험자가 고른 지시문에 달려 있다. 보류 규약 원샷 팔은 이번에 두지 않았다.
8. **모델이 교란 변수다.** 원샷 팔은 `planner` 역할 모델(effort medium) 한 번 호출이고, 에이전트는 노드별 모델을 쓴다. 차이에는 시스템 구조뿐 아니라 모델·샘플링 차이가 섞인다. 원샷 상태에 응답 모델을 기록한다.
9. NLI 필터는 결정론적이지만(NLI 모델 고정) 걸러진 뒤 남는 finding이 적으면 빈 집합끼리 Jaccard 1.0이 나와 L2가 부풀 수 있다. 빈 집합 쌍 수와 2차 지표, 회차별 집합(`consistency.json`의 `L2.<팔>.sets`)을 공개한다.
10. 원샷 팔에는 계산 도구가 없다. 원샷 L1의 일관성 차이에는 산술 오류도 섞일 수 있다.
11. ChEMBL·openFDA 응답이 실행 시점마다 같다고 가정한다. 응답이 바뀌면 에이전트 입력 재현에서 드러난다.

## 실행 절차
실행 전에 이 문서와 `app/eval/consistency.py`를 커밋한다. `report`는 머리에 사전 등록 문서의 마지막 커밋 해시·시각과 HEAD를 인쇄하고, 두 파일이 미추적이거나 커밋 뒤 바뀌었으면, 또는 커밋 시각보다 먼저 저장된 상태가 있으면 경고한다.
```
.venv/Scripts/python.exe -m app.eval.consistency run_l1_oneshot   # results/states/consistency_l1_oneshot/<drug>_<rep>.json
.venv/Scripts/python.exe -m app.eval.consistency run_l1_inputs    # results/states/consistency_l1_inputs/
.venv/Scripts/python.exe -m app.eval.consistency run_oneshot      # results/states/consistency_oneshot/
.venv/Scripts/python.exe -m app.eval.consistency run_agent        # results/states/consistency_agent/
.venv/Scripts/python.exe -m app.eval.consistency report           # results/CONSISTENCY_REPORT.md, results/consistency.json (토큰 0)
```
상태 파일이 있으면 건너뛰므로 중단 후 같은 명령으로 재개한다. 상태 쓰기는 원자적이다(임시 파일 → `os.replace`). `report`는 일부 상태만 있어도 돌고 완료 개수를 표시한다.

## 사후 분석
이 문서에 없는 분석은 모두 "사후"로 표기한다. '이미 본 것'의 L2 수치(고친 시놉시스의 원샷·에이전트 3회 Jaccard, 설정이 다른 에이전트 실행 사이 Jaccard)는 이 문서를 고치는 과정에서 계산한 사후 값이며 1차 결과가 아니다.
